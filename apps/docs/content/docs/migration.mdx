Yolk packages are canary-stage. APIs can change between canary releases.

## Version rule

Keep every public package on the same canary version:

```bash
pnpm add @yolk-sdk/agent@canary @yolk-sdk/mcp@canary @yolk-sdk/knowledge@canary @yolk-sdk/connectors@canary @yolk-sdk/sandbox@canary @yolk-sdk/vercel-workflows@canary
```

`@yolk-sdk/harness` is introduced after `0.1.0-canary.76`. It is unavailable in `0.1.0-canary.76` and earlier. Choose a newer matching canary once available, and keep it on the same lockstep version as the other public packages.

Check installed versions:

```bash
pnpm list '@yolk-sdk/*'
```

Do not mix versions unless a release note explicitly says it is safe.

## Recent canary migrations

### Next canary: chat streaming, Anthropic tool results, union tool schemas

These `@yolk-sdk/agent` behavior changes target the next matching canary. See [Go setup](./integrations/provider-setup#opencode-go) and [troubleshooting](./troubleshooting).

- OpenAI Chat Completions transport stays one JSON body by default. `OpenAiProviderConfig.streaming:
  true` requests incremental `chat.completion.chunk` SSE deltas with usage; unterminated streams
  fail `invalid_response` without `Done`. OpenCode Go chat always streams. Only enable streaming
  against endpoints that serve chat SSE.
- Anthropic tool-result blocks omit `is_error` when the result carries no error flag, keeping
  follow-up request bodies valid. Explicit boolean flags are still serialized.
- `makeTool` may add root `type: "object"` to typeless object-only `anyOf`/`oneOf` unions for strict
  OpenAI-compatible upstreams. Call validation still uses the original Effect Schema.
- Chat Completions and Responses HTTP failures copy the envelope string `code` (falling back to
  `type`) into `provider.providerCode`; raw upstream bodies stay out of typed failures.

### Next canary: selected branded identities and typed connector actions

These source changes target a future matching canary. Identity wire representations stay strings,
but typed host implementations and fixtures must migrate; this is a breaking pre-1.0 minor change.

| Surface                         | Migration                                                                                                                          |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `@yolk-sdk/knowledge/documents` | Use `KnowledgeScopeId` and `KnowledgeDocumentId` in models, store adapters, chunking, ingestion, and search scopes.                |
| `@yolk-sdk/harness/inbox`       | Forward live `DrainToken` and `ParkGeneration` values; custom Inbox/Driver adapters must return the corresponding brands.          |
| `@yolk-sdk/sandbox`             | `normalizeWorkspaceCwd` now returns `NormalizedWorkspaceCwd`; raw command `cwd` remains a string.                                  |
| `@yolk-sdk/connectors/fortnox`  | File discovery uses canonical `FortnoxGivenNumber`; preview downloads require `FortnoxDocumentNumber`. Archive IDs remain strings. |

Effect-decode external/persisted strings with the exported schema; `.make` is synchronous and is
appropriate for trusted constants or freshly minted values. Do not cast raw IDs or annotate ORM
columns to bypass decoding. For example, inside an Effect program:

```ts
import * as Schema from 'effect/Schema'
import { KnowledgeDocumentId } from '@yolk-sdk/knowledge/documents'

const documentId = yield * Schema.decodeUnknownEffect(KnowledgeDocumentId)(rawDocumentId)
```

This is a fragment; `rawDocumentId` is host-owned input. Brands do not establish authorization,
ownership, existence, or freshness. Harness token schemas remain nominal-only and accept arbitrary
strings; runtime stale/foreign-token decisions remain authoritative. Do not restore old in-memory
park generations by decoding them after restart.

Fortnox file metadata now rejects nonnumeric `givenNumber` values through the canonical schema.
Preview identifiers use the same validator as invoice reads and complete-segment URL encoding,
rather than unrelated archive-ID restrictions.

`defineAction` additionally returns `TypedConnectorAction` with `executeTyped`. It accepts decoded
`InputSchema.Type`, validates using `Schema.toType(inputSchema)`, and retains the output type. It
does not reapply wire transformations: a `NumberFromString` field is a number at this entrypoint.
Existing dynamic `execute`/`invoke` paths remain compatible and decode encoded input as before.
External output validation remains the implementation's responsibility.

### Next canary: Effect rc.115

This source upgrade targets `effect@4.0.0-rc.115`; it is not a claim that an already-published canary uses that version. Upgrade matching Yolk packages and Effect together when the corresponding canary is available.

- Use `Schema.TaggedError`, `Schema.fromJsonString(Schema.Unknown)` and capitalized `Config.String` / `Config.Int` / `Config.Redacted` APIs.
- Schema construction now follows schema field order, including `_tag` first. JSON field values and optional presence are unchanged, but raw serialized bytes can differ. Do not depend on beta.80's property insertion order.
- `Schema.SchemaError` is now a native `Error`. Synchronous schema makers throw a native error with a `SchemaIssue.Issue` cause; Effectful makers fail with the issue. Keep typed owner errors and inspect retained causes rather than matching old diagnostic text.
- Tool schemas use Effect's canonical JSON representation. Prefer finite-number schemas for JSON inputs; definition references may acquire an `Encoded` suffix. Empty-struct tools still advertise a closed empty object. Custom JSON Schema output must still pass Yolk's portable-data boundary.

### Next canary: optional harness and collector recovery

`@yolk-sdk/harness` is a new optional run-lifecycle package (coordinator, store, inbox, drivers, outcomes). It is not the agent loop and does not add a Workflow driver. It is introduced after `0.1.0-canary.76` and unavailable in `0.1.0-canary.76` and earlier. Choose a newer matching canary once available.

Loop composition now names `makeAgentLoopLayer`, `decorateLLMProvider`, `collectModelTurn`, and `collectModelTurnAttempt`. Omitted tools use `ToolExecutor.unavailable`.

Kernel streams that end with zero `Done` events fail as `LLMError` `invalid_response` / `retryable: false` with `responseIssue: 'missing_done'`. That is not automatic provider or tool replay. Codex additionally synthesizes `Done` only for the specific missing-final-`output` error; see [OpenAI Codex](./integrations/model-providers#openai-codex).

Overflow compact now refuses to run after published output (`overflowCompactionMayRun`). Durable persist-then-retry stays host-owned.

`attemptModelTurn` classifies one `runModelTurn` after that stream's inner retries. It does not add an outer retry loop. A finalized collector failure (`collectModelTurn` / `collectModelTurnAttempt`) is not host-chosen recovery; see [Troubleshooting](./troubleshooting#collector-failed-versus-host-chosen-recovery) and [Harness composition](./vercel-workflows/harness-composition).

### Next canary: owned JSON data and voice session resources

`ToolDef.parameters` now requires `ToolJsonSchema`: boolean or plain JSON-object representation.
Constructors/raw decode reject nonfinite values, cycles, exotics and accessor fields; accessors are
not executed. Dense ordinary arrays, null-prototype objects and DAG aliases are legal. Admitted
identity is retained, not frozen. Use `decodeToolJsonSchema` / `decodeToolJsonSchemaObject` for raw
inputs (`Option`); JSON Schema semantic/provider validation is separate. Tool arguments/results and
HITL stay opaque. Background envelopes preserve boolean argument schemas. MCP discovery requires
the object arm and retains typed validation errors and the omitted-schema default.

`OpenAiProviderConfig.extraBody` now takes JSON-object input (`OpenAiRequestExtras`). Build inert
JSON data, not getter-backed configuration. Lowering snapshots surviving enumerable own fields,
discarding canonical request keys unread. Surviving accessors/exotics/invalid JSON fail with fixed
`Invalid … extraBody JSON: expected a JSON object` before HTTP. The snapshot preserves JSON values,
own `__proto__`/`constructor` and DAG aliases; it does not retain input identity. Root symbols/hidden
fields are omitted; nested symbols/hidden fields and extra array properties fail. Final request
serialization remains independently checked. Proxy reflection traps are not guaranteed inert.

Connector integration/binding `metadata` now uses `PortableMetadata`. Convert Dates, Maps, custom
instances and other rich values to explicit JSON first. Decode/make return non-frozen snapshots with
null-prototype objects and dense arrays; aliases share copied nodes, cycles/accessors/exotics fail.
Absent metadata stays absent. Config, credential secrets, error `underlying` and host DB schemas are
unchanged; this is not a database migration.

`makeVoiceController` now requires `VoiceTransport` instead of `options.transport`. Wrap existing
transport values with `Effect.provideService`, or use `VoiceSession.layer` with a transport layer,
codec/tool endpoint and optional `eventLog`. Browser/WebSocket transport layer constructors are
exported from their existing subpaths. Configured logging runs without an external event consumer;
no `eventLog` means no ambient outbox capture. Keep provided layers alive through the full session
usage, or use `Layer.buildWithScope` for an explicit lifetime. `Layer.succeed` injects externally
owned values; it does not allocate/finalize resources. These are breaking 0.x changes (minor).

### Next canary: makeTool SchemaError and workflow CommitError callbacks

`makeTool({ invalidParamsMessage })` on `@yolk-sdk/agent/tools` is now
`(error: Schema.SchemaError) => string` (was `(error: unknown) => string`). Only
`Schema.decodeUnknownEffect` on `parameters` invokes it (validate and execute). The decode error
is passed through unwrapped. Default remains `Invalid ${name} arguments: ${String(error)}`,
including the `SchemaError(...)` wrapper. In Effect rc.115, `SchemaError` extends native `Error`,
but the wrapper remains part of this tool-message contract; do not switch the default to `.message`. Existing `(error: unknown) => string` callbacks remain assignable. No new
export subpath; `MakeToolOptions` is still not barreled from `@yolk-sdk/agent/tools`.

`commitThenWriteTerminalEvent({ writeCommitError })` on `@yolk-sdk/vercel-workflows` is now
`(error: CommitError) => …`, where `CommitError` is the existing generic on `commit`. The producer
is `Effect.matchEffect` `onFailure` of `commit`; typed failures—not defects or interruptions—are
passed to the callback. Result tags still carry `commitError` and `error` as `unknown`; those fields are not
tightened. Existing `(error: unknown) => …` callbacks remain assignable. No generic expansion or
export-map change.

### Next canary: voice void addTrack, finite voice argument JSON, MCP protocol owners

`WebRtcPeerConnectionLike.addTrack` on `@yolk-sdk/agent/voice/browser` is now a void command (was
unused `unknown`). Hosts and fakes must not read a sender. Real `RTCPeerConnection.addTrack`
remains assignable. No export-map change.

Voice raw-argument JSON on `@yolk-sdk/agent/voice`: `protocolToolCallFromVoice` and
`decideVoiceToolCall` admit finite JSON. Actual `null` / `false` / `0` still admit as those values.
Raw text `1e999` uses the existing malformed fallbacks instead of publishing `Infinity`:
projection params are the raw string `'1e999'`; approval display params are
`{ argumentsJson: '1e999' }`. Nested overflow such as `{"n":1e999}` takes the same fallbacks. Do
not demonstrate with `JSON.stringify(Infinity)` (that is `null`). `protocolToolCallFromVoice` still
returns `ToolCall`. Execution schema validation, approval identifiers, and gates are unchanged.

`@yolk-sdk/mcp/client` and `@yolk-sdk/mcp/protocol` add Schema owners `InitializeClientInfo`,
`InitializeParams`, `InitializedNotification`, and `ToolsCallParams` (same `protocol.ts`; no new
export subpath). Prefer Schema owners for new construction. Compatibility `makeJsonRpcRequest`,
`makeInitializeParams`, and `makeInitializedNotification` remain and build through those schemas.
`makeJsonRpcRequest` still omits `params` when `undefined`; when params are present, getter access
order stays `id`, `method`, `params`, `params`.

### Next canary: OpenAI JSON admission, Realtime parameters, and Gmail finite JSON

OpenAI Chat Completions and Responses lowering now requires `ToolDef.parameters` and tool-call
`params` to decode as `Schema.Json`. Non-JSON values fail as non-retryable `LLMError`
`provider_error` before transport. `ToolDef.parameters` now has the admission contract above;
`ToolCall.params` remains `Schema.Unknown`. Public
Codex wrapper `OpenAiCodexTool.parameters` is still `unknown`. Optional body fields are omitted
unless present. After lone-surrogate rewrite, request bodies are decoded as JSON again and fail
rather than skipping. Inbound HTTP JSON admits `Schema.Json` (`invalid_response` on failure).
Responses SSE JSON admits `Schema.Json`: non-object JSON events are ignored; malformed non-JSON
event text fails. First `response.completed` remains terminal. HTTP error bodies stay raw text.

The former extraBody spread/getter contract is superseded by the portable snapshot migration above.
Canonical fields are discarded unread and surviving accessors are rejected without execution.
Composed-body admission after lone-surrogate rewriting remains the final serialization defense.

Public Realtime `OpenAiRealtimeFunctionTool.parameters` and `openAiRealtimeToolParameters` now take
`Schema.Json`. Non-JSON advertisement fails `VoiceToolBridgeError`: sync helpers throw; Effect
helpers fail in the typed channel. Mapper defects stay defects. Union-root lowering uses a `Map` so
own `__proto__` / `constructor` merge instead of prototype assignment.

Gmail `get_thread` / `list_attachments` MIME `payload` admits `Schema.Json` after JSON parse.
Best-effort optional size omission (`-1`, `1.5`, `null`, `"12"`, missing) and sibling preservation
are unchanged. Finite JSON is a deliberate whole-payload reject: raw HTTP `1e999` → `Infinity` →
`ConnectorError` `validation_failed` (`Invalid response shape`). Public action classes,
`GmailUnknownOutput`, and `gmail.get_attachment` are unchanged. Independent raw wire/key goldens were
not migrated.

### Next canary: Claude JSON tool payloads and React constructor usage

Claude lowering now requires `ToolDef.parameters` and `ToolCall.params` to decode as `Schema.Json`.
Non-JSON values fail as non-retryable `LLMError` with `cause: 'provider_error'`. `ToolDef.parameters`
now has the admission contract above; `ToolCall.params` remains opaque. After lone-surrogate
rewrite, the Claude request body is decoded as JSON again and fails rather than skipping.
HTTP error bodies that are not JSON still classify from status.

`useAgentChat` now dispatches the existing `AgentChatAction` constructors and returns the existing
hook-result constructors (`AgentChatSubmitResult`, `AgentChatDeleteTurnResult`, and siblings).
Those values are `Data.taggedEnum` plain objects with `_tag` last, not Equal/Hash classes. Prefer
constructors and `$is`; omit absent optionals. Duration descriptors still use
`Schema.TaggedStruct.make`. No new React export paths.

MCP production client/protocol/index are unchanged in this batch. App-owned knowledge-search File
identity, Cloudflare occupancy, and example UI wiring are not `@yolk-sdk/*` APIs.

### Next canary: canonical tagged constructors

Several public ADTs that were type-only, or that callers built as handwritten `{ _tag }` objects,
now have constructors on existing subpaths. No new export paths.

`Data.taggedEnum` builds **plain objects** `{ ...fields, _tag }` (`_tag` last). They are not
`Equal`/`Hash` Data classes. `Schema.Class` / `Data.TaggedClass` remain class instances.
`Schema.TaggedStruct.make` constructs validated plain values. Prefer constructors; omit absent optionals.
Existing `_tag` reads still work.

| ------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `@yolk-sdk/agent/protocol`      | `PlainHitlResponse` type-only; helpers wrote `_tag` (often first)   | Value `PlainHitlResponse.QuestionResponse` / `.ToolApprovalResponse`; helpers omit absent optionals                                                                      |
| `@yolk-sdk/agent/runtime`       | `export type { RuntimeRequest }` only                               | `export { runRuntime, RuntimeRequest }` (value carries the type)                                                                                                         |
| `@yolk-sdk/agent/react`         | Chat ADTs type-only                                                 | Values `AgentChatPart`, `ChatToolState`, `AgentChatItem`, `ToolRunState`, message mutators, `AgentChatAction`, hook results; `ToolDurationKnown` / `ToolDurationUnknown` |
| `@yolk-sdk/harness/outcome`     | `StepOutcome` / `HitlMatch` / overflow result type-only or internal | Public `StepOutcome`, `HitlMatch`, `OverflowCompactionResult`                                                                                                            |
| `@yolk-sdk/harness/inbox`       | Private decision constructors                                       | Public `HitlDecision`, `PauseDecision`, `RecoveryAttempt`, `RecoveryAdmission`, `DrainBegin`                                                                             |

JSON key order for `Data.taggedEnum` values puts `_tag` last. Do not treat that as `Equal`/`Hash`.
The knowledge **value** `KnowledgeSearchScope` is the single-id constructor; the **type** remains the union.
A missing source URL is not a storage object id; do not invent locators to satisfy `.make`.

### Next canary: host-only connector file retrieval and writes

New byte helpers on existing connector subpaths are host-only. They are not connector actions and
`makeConnectorToolModule` does not serialize them. Provide `ConnectorBinaryHttpClient` and/or
`ConnectorBinaryWriteHttpClient`, keep streamed limits and connection-time network policy in the
host, and keep raw bytes out of generic tool JSON. Dropbox create is strict add; Dropbox update
requires a stable `id:` and expected revision; OneDrive update requires `acknowledgeOverwrite: true`
and is unconditional, not compare-and-swap; R2 puts stay ETag-conditional. Fortnox `connectfile` and
`archive` slots are opt-in and are **not** on `FortnoxCombinedOAuthCredentialSlot`. Drive content
defaults to `drive.file`; `contentAccess: 'readonly'` is host-only `drive.readonly`.

Passing whole `FortnoxConnector` or `TodoistConnector` into `makeConnectorToolModule` now also
exposes `fortnox.list_supplier_invoice_files` and `todoist.list_comments`. See
[Transfer connector files](./connectors/files).

### Next canary: background tool admission and bounded child observations

Tools with `background: true` remain unchanged without a `BackgroundToolHost`. When a host is
supplied to `resolveTools`, activated tools require `{ execution, arguments }` rather than raw
business parameters. Update exhaustive event/state consumers for `ToolExecutionAccepted` and
`Accepted`: admission settles the call but does not complete the work. Preserve the full call and
`acceptance` receipt through persistence, replay, hydration, and next-turn cleanup.

Store and return activated approval request IDs unchanged as opaque, potentially long values;
they bind the exact tool, execution mode, and arguments. Resolve voice/realtime toolsets without a
background host, even for foreground calls. Custom voice decision consumers must handle `Deny`;
Effect hosts can use the typed realtime config builders to recover from `VoiceToolBridgeError`.
See [Model-chosen background execution](./agent/tools-hitl#let-the-model-choose-background-execution).

Explicitly include the `question` definition in the loop's enabled tools to allow question HITL.
Omitting it now returns an unavailable-tool result without pausing, even with a replayed answer.

`awaitWorkflowChild` read/sleep callbacks now receive zero-based attempt indices; existing
zero-argument callbacks remain valid. Hosts can stop observation at their own ceiling without
claiming the child terminated. For a nonterminal `subagent` result, use the matching
`subagent_observation` marker and logical child ID to avoid a false `SubagentCompleted` event.
See [Nonterminal child observations](./agent/tools-hitl#nonterminal-child-observations) and
[Bounded child observations](./vercel-workflows/step-contracts#bounded-child-observations).

### Next canary: private attachment resolution

Use `resolveMessageAttachmentSources` or `resolveMessagesAttachmentSources` from
`@yolk-sdk/agent/protocol` to resolve media in a request-local transcript copy. These helpers do not
automatically sign refs or add provider media support. Keep authorization/signing inside each
provider attempt, including overflow retry, while persisted messages retain refs. See
[Resolve private attachments](./guides/private-attachments).

Gmail discovery now omits malformed optional attachment sizes; zero remains valid. Public
`GmailThreadAttachment` schema decoding requires any present `size` to be a nonnegative integer.
Update stored-metadata decoders and fixtures that previously supplied negative or fractional sizes;
provider sizes still do not prove actual decoded byte length.

### Next canary: opt-in durable subagents

Inline subagent registrations remain compatible. Hosts opting into `background: true` must
implement durable child launch and later status/wait observations. Return
`makeSubagentAcceptedToolResult` for launch acceptance; it is not final child output and adds no
child usage or `SubagentCompleted`. Status/wait tools, storage, ownership, and Stop policy remain
host-owned. See [Background subagents](./agent/tools-hitl#background-subagents).

Custom Workflow tool-batch hosts can use `prepareToolBatch` inside a preflight step and
`orchestrateWorkflowToolBatch` / `awaitWorkflowChild` in orchestration. Pending HITL fences all
launches. Do not wrap an independent child loop in a parent step, and handle partial results plus
failures before returning the batch result. See
[Independent child orchestration](./vercel-workflows/step-contracts#independent-child-orchestration).

### `0.1.0-canary.72`: Outlook optional read inputs

`outlook.list_messages` and `outlook.search_messages` now normalize null/blank optional strings
and null page sizes to `undefined` for direct calls and generated agent tools. Existing non-blank
values are unchanged; search still requires `query`, and application access still requires a
non-blank `mailbox`. See [Optional Outlook read inputs](./integrations/connectors#optional-outlook-read-inputs)
for the accepted fields and validation rules.

### `0.1.0-canary.57`: remove Codex output-token configuration

ChatGPT subscription Codex rejects `max_output_tokens`. Stop passing `maxOutputTokens` to
`makeOpenAiCodexProviderLayer` and `toOpenAiCodexRequestBody`; the optional deprecated field remains
accepted but is ignored for compatibility. Keep host-owned input/context budgeting separate from
provider output configuration.

### `0.1.0-canary.55`: rename task delegation to subagent

The model-facing `task` delegation tool is now named `subagent` to distinguish isolated child-agent
runs from durable application tasks. Update tool-name checks and replace the public tools helpers:

| Previous                         | Replacement                            |
| -------------------------------- | -------------------------------------- |
| `makeTaskToolModule`             | `makeSubagentToolModule`               |
| `makeNonRecursiveTaskToolModule` | `makeNonRecursiveSubagentToolModule`   |
| `makeTaskToolDef`                | `makeSubagentToolDef`                  |
| `makeTaskToolRegistration`       | `makeSubagentToolRegistration`         |
| `makeTaskToolResult`             | `makeSubagentToolResult`               |
| `formatTaskResult`               | `formatSubagentResult`                 |
| `taskToolName`                   | `subagentToolName`                     |
| `taskSubagentRunId`              | `subagentToolRunId`                    |
| `Task*` public types             | corresponding `Subagent*` public types |

The old names are removed rather than aliased. Hosts must expose `subagent`, omit it from child
agent toolsets, and update UI/tool-call matching from `task` to `subagent`.

### `0.1.0-canary.52`: Codex omits the unsupported output limit

ChatGPT subscription Codex requests no longer send `max_output_tokens` because the endpoint rejects
that field. In that historical canary, `OpenAiCodexProviderConfig.maxOutputTokens` remained required
host configuration but was not serialized. Since `0.1.0-canary.57`, it is optional, deprecated,
and ignored; remove it from Codex provider construction.

### `0.1.0-canary.48`: required provider output limits

Provider constructors no longer infer output-token limits or apply hidden fallbacks. Supply the
required field for the selected adapter:

| Provider config                 | Required output-limit field | Previous behavior                               |
| ------------------------------- | --------------------------- | ----------------------------------------------- |
| `OpenAiProviderConfig`          | `maxCompletionTokens`       | defaulted to `4096`                             |
| `OpenAiCodexProviderConfig`     | `maxOutputTokens`           | historically required but omitted from requests |
| `AnthropicClaudeProviderConfig` | `maxTokens`                 | defaulted to `8192`                             |

In that canary, the public `toOpenAiRequestBody`, `toOpenAiCodexRequestBody`, and
`toAnthropicClaudeRequestBody` lowerers also required their limit configuration. Since
`0.1.0-canary.57`, the Codex compatibility config is optional; OpenAI API and Anthropic lowerers still require their
host-owned output limits. The env-backed
`OpenAiProviderLayer` now requires integer `OPENAI_MAX_COMPLETION_TOKENS` alongside
`OPENAI_API_KEY`. Keep these values in host-owned model configuration.

### `0.1.0-canary.47`: Claude output limits

Anthropic Claude turns that stop at `max_tokens` now fail as non-retryable `invalid_response`
instead of reporting normal completion. Stream consumers may observe partial text, but no normal
`Done` follows. Increase `maxTokens`, request shorter output, or adjust host output policy.

### `0.1.0-canary.46`: Anthropic context overflow

Anthropic prompt-too-long responses now classify as non-retryable `context_overflow`. Generic loop
retry does not retry them. Hosts with compaction can use `makeContextOverflowRetryProvider` to
compact and retry once.

### `0.1.0-canary.46`: normalized Gmail threads

`gmail.get_thread` no longer accepts only `{ threadId }` or returns Gmail's raw thread wire payload.
Use this fragment to pass an explicit format:

```ts
import { GmailGetThreadInput } from '@yolk-sdk/connectors/google'

const input = GmailGetThreadInput.make({
  threadId: hostGmailThreadId,
  format: 'full'
})
```

Allowed formats are `full`, `metadata`, and `minimal`; use `full` when decoded bodies are required.
Read normalized `messages[].body`, `bodyMimeType`, `headers`, and `attachments` instead of Gmail
`payload`, MIME parts, or `body.data`. Thread output contains attachment metadata only. When
`attachmentId` exists, fetch content through `gmail.get_attachment` with the parent message `id` as
`messageId`. Gmail inline attachments may omit `attachmentId`; their content is intentionally absent
from normalized thread output and cannot be fetched through that action.

## Upgrade checklist

1. Update all `@yolk-sdk/*` dependencies together.
2. Run typecheck and tests in your host app.
3. Search for changed subpath imports.
4. Re-run one agent loop with the fake provider.
5. Re-run one real provider smoke test.
6. Re-run one tool call, one HITL pause/resume, and one stream reconnect path if your app uses them.
7. Re-check connector credentials and OAuth scopes if connector packages changed.
8. Re-check sandbox lifecycle and Workflow terminal-event ordering if platform packages changed.

| Providers    | auth config, model capabilities, output limits, usage/error metadata |
| Tools        | registration metadata, access levels, approval semantics             |
| MCP          | remote/local config, result adaptation, HTTPS policy                 |
| Knowledge    | store contracts, search request shape, agent tool options            |
| Connectors   | action ids, input/output schemas, credential slots, config keys      |
| Sandbox      | lifecycle defaults, command result shape, provider adapter options   |
| Workflows    | callback contracts, terminal status, retry/default behavior          |
| Harness      | drain/token contracts, claim vs Inbox persistence, recovery budgets  |

## Safe migration pattern

Create one compatibility boundary in your app for each package area:

| Boundary              | Owns                                                      |
| --------------------- | --------------------------------------------------------- |
| Agent runtime adapter | provider layer, loop config, enabled tools, stream format |
| Tool catalog          | app-owned tools, connector tools, MCP tools, approvals    |
| Persistence adapter   | transcript/session event store and replay repair          |
| Credential adapter    | OAuth/API token resolution and refresh                    |
| UI adapter            | event projection, retry display, HITL controls            |

Then most package changes affect one adapter instead of the entire app.

## Stable import habit

Use public subpaths only:

```ts
import { runRuntime } from '@yolk-sdk/agent/runtime'
import { listRemoteMcpServerTools } from '@yolk-sdk/mcp/client'
import { GoogleConnector } from '@yolk-sdk/connectors/google'
```

Avoid root imports for feature APIs and never import from package `src/*` internals.

## Before filing an issue

- exact package versions
- Node version
- runtime environment
- relevant public subpath imports
- minimal reproduction using `FauxProvider` when possible
- terminal `AgentError` or typed provider/tool error metadata
