Yolk packages are canary-stage. APIs can change between canary releases.

## Version rule

Keep every public package on the same canary version:

```bash
pnpm add @yolk-sdk/agent@canary @yolk-sdk/mcp@canary @yolk-sdk/knowledge@canary @yolk-sdk/connectors@canary @yolk-sdk/sandbox@canary @yolk-sdk/vercel-workflows@canary
```

Check installed versions:

```bash
pnpm list '@yolk-sdk/*'
```

Do not mix versions unless a release note explicitly says it is safe.

## Recent canary migrations

### Next canary: private attachment resolution

Use `resolveMessageAttachmentSources` or `resolveMessagesAttachmentSources` from
`@yolk-sdk/agent/protocol` to resolve media in a request-local transcript copy. These helpers do not
automatically sign refs or add provider media support. Keep authorization/signing inside each
provider attempt, including overflow retry, while persisted messages retain refs. See
[Resolve private attachments](./guides/private-attachments).

Gmail discovery now omits malformed optional attachment sizes; zero remains valid. Public
`GmailThreadAttachment` schema decoding requires any present `size` to be a nonnegative integer.
Update stored-metadata decoders and fixtures that previously supplied negative or fractional sizes;
provider sizes still do not prove actual decoded byte length.

### Next canary: opt-in durable subagents

Inline subagent registrations remain compatible. Hosts opting into `background: true` must
implement durable child launch and later status/wait observations. Return
`makeSubagentAcceptedToolResult` for launch acceptance; it is not final child output and adds no
child usage or `SubagentCompleted`. Status/wait tools, storage, ownership, and Stop policy remain
host-owned. See [Background subagents](./agent/tools-hitl#background-subagents).

Custom Workflow tool-batch hosts can use `prepareToolBatch` inside a preflight step and
`orchestrateWorkflowToolBatch` / `awaitWorkflowChild` in orchestration. Pending HITL fences all
launches. Do not wrap an independent child loop in a parent step, and handle partial results plus
failures before returning the batch result. See
[Independent child orchestration](./vercel-workflows/step-contracts#independent-child-orchestration).

### `0.1.0-canary.72`: Outlook optional read inputs

`outlook.list_messages` and `outlook.search_messages` now normalize null/blank optional strings
and null page sizes to `undefined` for direct calls and generated agent tools. Existing non-blank
values are unchanged; search still requires `query`, and application access still requires a
non-blank `mailbox`. See [Optional Outlook read inputs](./integrations/connectors#optional-outlook-read-inputs)
for the accepted fields and validation rules.

### `0.1.0-canary.57`: remove Codex output-token configuration

ChatGPT subscription Codex rejects `max_output_tokens`. Stop passing `maxOutputTokens` to
`makeOpenAiCodexProviderLayer` and `toOpenAiCodexRequestBody`; the optional deprecated field remains
accepted but is ignored for compatibility. Keep host-owned input/context budgeting separate from
provider output configuration.

### `0.1.0-canary.55`: rename task delegation to subagent

The model-facing `task` delegation tool is now named `subagent` to distinguish isolated child-agent
runs from durable application tasks. Update tool-name checks and replace the public tools helpers:

| Previous                         | Replacement                            |
| -------------------------------- | -------------------------------------- |
| `makeTaskToolModule`             | `makeSubagentToolModule`               |
| `makeNonRecursiveTaskToolModule` | `makeNonRecursiveSubagentToolModule`   |
| `makeTaskToolDef`                | `makeSubagentToolDef`                  |
| `makeTaskToolRegistration`       | `makeSubagentToolRegistration`         |
| `makeTaskToolResult`             | `makeSubagentToolResult`               |
| `formatTaskResult`               | `formatSubagentResult`                 |
| `taskToolName`                   | `subagentToolName`                     |
| `taskSubagentRunId`              | `subagentToolRunId`                    |
| `Task*` public types             | corresponding `Subagent*` public types |

The old names are removed rather than aliased. Hosts must expose `subagent`, omit it from child
agent toolsets, and update UI/tool-call matching from `task` to `subagent`.

### `0.1.0-canary.52`: Codex omits the unsupported output limit

ChatGPT subscription Codex requests no longer send `max_output_tokens` because the endpoint rejects
that field. In that historical canary, `OpenAiCodexProviderConfig.maxOutputTokens` remained required
host configuration but was not serialized. Since `0.1.0-canary.57`, it is optional, deprecated,
and ignored; remove it from Codex provider construction.

### `0.1.0-canary.48`: required provider output limits

Provider constructors no longer infer output-token limits or apply hidden fallbacks. Supply the
required field for the selected adapter:

| Provider config                 | Required output-limit field | Previous behavior                               |
| ------------------------------- | --------------------------- | ----------------------------------------------- |
| `OpenAiProviderConfig`          | `maxCompletionTokens`       | defaulted to `4096`                             |
| `OpenAiCodexProviderConfig`     | `maxOutputTokens`           | historically required but omitted from requests |
| `AnthropicClaudeProviderConfig` | `maxTokens`                 | defaulted to `8192`                             |

In that canary, the public `toOpenAiRequestBody`, `toOpenAiCodexRequestBody`, and
`toAnthropicClaudeRequestBody` lowerers also required their limit configuration. Since
`0.1.0-canary.57`, the Codex compatibility config is optional; OpenAI API and Anthropic lowerers still require their
host-owned output limits. The env-backed
`OpenAiProviderLayer` now requires integer `OPENAI_MAX_COMPLETION_TOKENS` alongside
`OPENAI_API_KEY`. Keep these values in host-owned model configuration.

### `0.1.0-canary.47`: Claude output limits

Anthropic Claude turns that stop at `max_tokens` now fail as non-retryable `invalid_response`
instead of reporting normal completion. Stream consumers may observe partial text, but no normal
`Done` follows. Increase `maxTokens`, request shorter output, or adjust host output policy.

### `0.1.0-canary.46`: Anthropic context overflow

Anthropic prompt-too-long responses now classify as non-retryable `context_overflow`. Generic loop
retry does not retry them. Hosts with compaction can use `makeContextOverflowRetryProvider` to
compact and retry once.

### `0.1.0-canary.46`: normalized Gmail threads

`gmail.get_thread` no longer accepts only `{ threadId }` or returns Gmail's raw thread wire payload.
Use this fragment to pass an explicit format:

```ts
import { GmailGetThreadInput } from '@yolk-sdk/connectors/google'

const input = GmailGetThreadInput.make({
  threadId: hostGmailThreadId,
  format: 'full'
})
```

Allowed formats are `full`, `metadata`, and `minimal`; use `full` when decoded bodies are required.
Read normalized `messages[].body`, `bodyMimeType`, `headers`, and `attachments` instead of Gmail
`payload`, MIME parts, or `body.data`. Thread output contains attachment metadata only. When
`attachmentId` exists, fetch content through `gmail.get_attachment` with the parent message `id` as
`messageId`. Gmail inline attachments may omit `attachmentId`; their content is intentionally absent
from normalized thread output and cannot be fetched through that action.

## Upgrade checklist

1. Update all `@yolk-sdk/*` dependencies together.
2. Run typecheck and tests in your host app.
3. Search for changed subpath imports.
4. Re-run one agent loop with the fake provider.
5. Re-run one real provider smoke test.
6. Re-run one tool call, one HITL pause/resume, and one stream reconnect path if your app uses them.
7. Re-check connector credentials and OAuth scopes if connector packages changed.
8. Re-check sandbox lifecycle and Workflow terminal-event ordering if platform packages changed.

## What can break during canary

| Area         | Watch for                                                            |
| ------------ | -------------------------------------------------------------------- |
| Protocol     | event names, message fields, terminal state, tool/HITL payloads      |
| Loop/runtime | required Effect services, runtime request shapes, stream semantics   |
| Client/React | projection state, transport headers, resume helpers                  |
| Providers    | auth config, model capabilities, output limits, usage/error metadata |
| Tools        | registration metadata, access levels, approval semantics             |
| MCP          | remote/local config, result adaptation, HTTPS policy                 |
| Knowledge    | store contracts, search request shape, agent tool options            |
| Connectors   | action ids, input/output schemas, credential slots, config keys      |
| Sandbox      | lifecycle defaults, command result shape, provider adapter options   |
| Workflows    | callback contracts, terminal status, retry/default behavior          |

## Safe migration pattern

Create one compatibility boundary in your app for each package area:

| Boundary              | Owns                                                      |
| --------------------- | --------------------------------------------------------- |
| Agent runtime adapter | provider layer, loop config, enabled tools, stream format |
| Tool catalog          | app-owned tools, connector tools, MCP tools, approvals    |
| Persistence adapter   | transcript/session event store and replay repair          |
| Credential adapter    | OAuth/API token resolution and refresh                    |
| UI adapter            | event projection, retry display, HITL controls            |

Then most package changes affect one adapter instead of the entire app.

## Stable import habit

Use public subpaths only:

```ts
import { runRuntime } from '@yolk-sdk/agent/runtime'
import { listRemoteMcpServerTools } from '@yolk-sdk/mcp/client'
import { GoogleConnector } from '@yolk-sdk/connectors/google'
```

Avoid root imports for feature APIs and never import from package `src/*` internals.

## Before filing an issue

Include:

- exact package versions
- Node version
- runtime environment
- relevant public subpath imports
- minimal reproduction using `FauxProvider` when possible
- terminal `AgentError` or typed provider/tool error metadata
