title: Vercel Workflows package
description: Run durable agent loops with host-owned Workflow steps.
---

Use `@yolk-sdk/vercel-workflows` when an agent run can outlive one HTTP request and should resume through Vercel Workflows.

Install:

```bash
pnpm add @yolk-sdk/vercel-workflows@canary effect workflow
```

## Wrap your Workflow

Your Workflow function stays in your app. Pass host-owned step functions into the package loop.

```ts
import { createHook } from 'workflow'
import { runVercelAgentWorkflow } from '@yolk-sdk/vercel-workflows'

export async function runAgentWorkflow(input: { request: unknown; context: unknown }) {
  'use workflow'

  return await runVercelAgentWorkflow({
    input,
    runModelStep,
    runToolBatchStep,
    closeStream,
    writeError,
    awaitInput: async awaitingInput => {
      using hook = createHook<unknown>({ token: awaitingInput.hookToken })
      return await hook
    }
  })
}
```

`runModelStep`, `runToolBatchStep`, `closeStream`, and `writeError` are app-owned `'use step'` functions. Keep provider calls, tools, persistence, telemetry, and Effect runtimes in those steps.

## Use Effect at route boundaries

Host routes can use `@yolk-sdk/vercel-workflows/effect` to start, replay, resume, and cancel runs with typed Effect errors while keeping Vercel's SDK underneath.

```ts
import { Effect } from 'effect'
import { VercelWorkflows } from '@yolk-sdk/vercel-workflows/effect'

const program = Effect.gen(function* () {
  const workflows = yield* VercelWorkflows
  const run = yield* workflows.start(runAgentWorkflow, [{ request, context }])
  const readable = yield* run.getReadable<Uint8Array>()

  return new Response(readable, {
    headers: { 'x-workflow-run-id': run.runId }
  })
}).pipe(Effect.provide(VercelWorkflows.layer))
```

Do not use the Effect API inside a `'use workflow'` function. Keep it in routes, actions, services, or tests.

## Resume HITL

When `runToolBatchStep` returns `awaitingInput`, the package calls `awaitInput`, waits for the hook result, then reruns the same tool batch with accumulated HITL responses.

Your app owns hook tokens, route auth, response validation, and request matching.

## Emit replay-safe stream events

Use `sequenceDurableAgentEvent` to add deterministic ids without writing. Use
`writeDurableAgentEvent` when you want the same sequencing plus an NDJSON write:

```txt
${streamId}:${turn}:${eventSequence}
```

Clients should de-dupe by `eventId` during resume/reconnect.

## Commit before terminal events

Durable streams should settle canonical host state before terminal events:

```txt
live events -> host durable commit -> terminal event -> workflow-owned close
```

Use `commitThenWriteTerminalEvent` when a step must commit host state before writing the terminal
event. The workflow loop or stream owner owns the final close.
