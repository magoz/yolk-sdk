Provider adapters implement `LLMProvider` for the agent loop. They translate Yolk messages/tools into vendor requests and normalize text, reasoning, tool calls, usage, retries, and provider errors back into Yolk events.

For copy-paste provider layer setup, see [Use model providers](./provider-setup).

## Available providers

| Provider               | Factory                            | Auth               | Notes                                                                                                               |
| ---------------------- | ---------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| OpenAI-compatible chat | `makeOpenAiProviderLayer`          | API key            | Chat Completions-style endpoint; `OpenAiProviderLayer` can read its API key and output limit through Effect Config. |
| Vercel AI Gateway      | `makeVercelAiGatewayProviderLayer` | API key or OIDC    | OpenAI-compatible Gateway endpoint with provider routing and model fallbacks.                                       |
| OpenCode Go            | `makeOpenCodeGoProviderLayer`      | API key            | Host-selected Chat Completions, Messages, or Responses protocol.                                                    |
| OpenAI Codex           | `makeOpenAiCodexProviderLayer`     | `OAuthAccessToken` | Responses API adapter with reasoning summaries and OAuth broker helpers.                                            |
| Anthropic Claude Code  | `makeAnthropicClaudeProviderLayer` | `OAuthAccessToken` | Claude Code-compatible adapter with Claude OAuth broker helpers.                                                    |
| xAI Grok subscription  | `makeXAiGrokProviderLayer`         | `OAuthAccessToken` | Responses adapter for Grok consumer subscriptions through the xAI CLI proxy.                                        |
| Faux provider          | `FauxProvider.layer(...)`          | none               | Test-only deterministic provider from `@yolk-sdk/agent/loop/testing`.                                               |

Provider output-token limits are host-owned when supported. OpenAI-compatible chat, Vercel AI
Gateway, OpenCode Go, Anthropic, and Grok require limits; ChatGPT Codex does not expose one. Yolk does not
maintain a model-limit catalog or apply hidden fallbacks.

## OpenAI-compatible chat

```ts
import { Layer, Redacted } from 'effect'
import { FetchHttpClient } from 'effect/unstable/http'
import { makeOpenAiProviderLayer } from '@yolk-sdk/agent/providers/openai/provider'

const ProviderLayer = makeOpenAiProviderLayer({
  apiKey: Redacted.make(hostOpenAiApiKey),
  maxCompletionTokens: hostModelConfig.maxOutputTokens
}).pipe(Layer.provide(FetchHttpClient.layer))
```

Use `chatCompletionsUrl` for generic OpenAI-compatible endpoints. Prefer the dedicated adapter below
for correct Vercel Gateway error attribution and routing options.

## Vercel AI Gateway

This is a server-side configuration fragment. The host supplies credentials and model policy:

```ts
import { Layer, Redacted } from 'effect'
import { FetchHttpClient } from 'effect/unstable/http'
import { makeVercelAiGatewayProviderLayer } from '@yolk-sdk/agent/providers/vercel/ai-gateway-provider'

const ProviderLayer = makeVercelAiGatewayProviderLayer({
  apiKey: Redacted.make(hostGatewayApiKeyOrOidcToken),
  maxCompletionTokens: hostModelConfig.maxOutputTokens,
  fallbackModels: hostFallbackModelIds,
  routing: { order: ['vertex', 'anthropic'] },
  extraHeaders: {
    'http-referer': hostPublicAppUrl,
    'x-title': hostAppName
  }
}).pipe(Layer.provide(FetchHttpClient.layer))
```

The adapter uses `https://ai-gateway.vercel.sh/v1/chat/completions` and defaults to a single JSON
completion. Set factory option `streaming: true` for SSE deltas. Independently set
`reasoningContent: true` to preserve compatible models' `reasoning_content` output (and the normalized `reasoning` thinking field some gateways emit, with `reasoning_content` taking precedence) and assistant
replay; streamed reasoning then surfaces as reasoning events, and replay spends input tokens.
Both options default to false. It lowers `maxCompletionTokens` to Gateway `max_tokens`. A run-level
`reasoningEffort` becomes `{ reasoning: { effort } }` by default; `reasoningEffortFormat: 'reasoning-effort'` sends the literal field instead (e.g. for DeepSeek-style hosts, with an optional `thinking: { type: 'enabled' | 'disabled' }` toggle merged into the request body). The host must
offer only effort values supported by its selected model. Pass model ids such as `provider/model`;
query Vercel's model catalog instead of hard-coding an SDK model union. `VercelAiGatewayProviderLayer` tries
`AI_GATEWAY_API_KEY`, then `VERCEL_OIDC_TOKEN`, and also reads integer
`AI_GATEWAY_MAX_COMPLETION_TOKENS`. Required auth and JSON headers override `extraHeaders`. Override
`chatCompletionsUrl` only with a trusted proxy because it receives the Bearer credential. Gateway
`finish_reason` values `length` and `content_filter` fail as non-retryable `invalid_response` rather
than reporting partial or filtered output as complete.

## OpenCode Go

Use `makeOpenCodeGoProviderLayer` from `@yolk-sdk/agent/providers/opencode/go-provider` with a
redacted API key, explicit `protocol`, and host-owned `maxOutputTokens`. See
[Go configuration](./provider-setup#opencode-go).

| Protocol           | Endpoint suffix     | Authentication | Transport                                       |
| ------------------ | ------------------- | -------------- | ----------------------------------------------- |
| `chat-completions` | `/chat/completions` | Bearer API key | SSE (`streaming: true`), normalized into events |
| `messages`         | `/messages`         | `x-api-key`    | SSE or JSON response                            |
| `responses`        | `/responses`        | Bearer API key | SSE or JSON response                            |

All endpoints default to `https://opencode.ai/zen/go/v1`. Choose the protocol advertised for the
selected model in [OpenCode's Go catalog](https://opencode.ai/docs/go/#endpoints); model availability
can change. Pass the API model ID without the `opencode-go/` CLI prefix. Yolk neither fetches the
catalog nor infers protocols or limits from model names.

Messages uses native system instructions and tool names, not Claude Code OAuth fingerprints.
Responses supports a host output limit and does not send Codex account or originator headers.
Go reports safe failures under provider ID `opencode_go`. Credentials, model capabilities, supported
reasoning efforts, allowance polling/persistence, and UI remain host-owned. Read allowance with
`fetchOpenCodeGoSubscriptionUsage` from `@yolk-sdk/agent/providers/opencode/usage`.

## OpenAI Codex

```ts
import { Layer } from 'effect'
import { FetchHttpClient } from 'effect/unstable/http'
import { makeOpenAiCodexProviderLayer } from '@yolk-sdk/agent/providers/openai/codex-provider'

const ProviderLayer = makeOpenAiCodexProviderLayer({
  token: hostOAuthAccessToken,
  defaultReasoningEffort: 'medium',
  reasoningSummary: 'auto'
}).pipe(Layer.provide(FetchHttpClient.layer))
```

The ChatGPT subscription endpoint rejects vendor `max_output_tokens`, so the adapter does not expose
an output-token limit. The optional deprecated `maxOutputTokens` field is ignored for compatibility.

Codex synthesizes `Done` only for the specific missing-final-`output` invalid response (the error
message includes `Missing key` and `["output"]`). The stop reason is `tool_use` if a tool call was
already emitted, otherwise `stop`. Unrelated invalid responses still fail. This is not generic
kernel `missing_done` recovery and does not replay tools.

OAuth helpers live in `@yolk-sdk/agent/providers/openai` and the exact `@yolk-sdk/agent/providers/openai/codex` subpath:

- `makeOpenAiCodexBrokerRequest`
- `makeOpenAiCodexTokenBrokerClient`
- `toOpenAiCodexOAuthAccessToken`
- `openAiCodexProviderId`
- OpenAI Codex OAuth URLs/constants
- `fetchOpenAiCodexSubscriptionUsage` from `@yolk-sdk/agent/providers/openai/codex-usage`

## xAI Grok subscription

Configuration fragment (the host supplies the token, model policy, and HTTP layer):

```ts
import { Layer } from 'effect'
import { FetchHttpClient } from 'effect/unstable/http'
import { makeXAiGrokProviderLayer } from '@yolk-sdk/agent/providers/xai/grok-provider'

const ProviderLayer = makeXAiGrokProviderLayer({
  token: hostOAuthAccessToken,
  maxOutputTokens: hostModelConfig.maxOutputTokens,
  clientVersion: hostGrokCliClientVersion
}).pipe(Layer.provide(FetchHttpClient.layer))
```

`clientVersion` is required and sent as `x-grok-client-version`: the CLI proxy version-gates
requests and rejects missing or outdated client versions with HTTP 426. The host owns the value and
should keep it current with the minimum Grok CLI version the proxy accepts.

This adapter sends consumer OAuth credentials only to the xAI CLI proxy by default. It does not use
`XAI_API_KEY` or `https://api.x.ai/v1`. OAuth helpers live in
`@yolk-sdk/agent/providers/xai` and `@yolk-sdk/agent/providers/xai/grok`:

- `makeXAiGrokAuthorizationUrl`
- `makeXAiGrokBrokerRequest`
- `makeXAiGrokTokenBrokerClient`
- `parseXAiGrokAuthorizationCode`
- `toXAiGrokOAuthAccessToken`
- `xAiGrokProviderId`
- Grok browser-PKCE/device-flow URLs and constants
- `fetchXAiGrokSubscriptionUsage` from `@yolk-sdk/agent/providers/xai/usage`

The public xAI CLI client uses a fixed loopback callback. The package exports browser-PKCE and
device-flow constants only; your host must implement the callback listener or complete device-code
request/polling, state/nonce and PKCE verification, token exchange, refresh serialization, secure
storage, token freshness/provider checks, and model discovery. Only override `responsesUrl` with a
trusted proxy because it receives the OAuth bearer. xAI controls the public CLI OAuth client and the
private, unsupported proxy contract; both may change and should be used only when permitted by xAI's
terms.

## Read subscription allowance

Claude, Codex, Grok, and OpenCode Go subscription connections can expose current allowance percentages and
reset windows. Claude normalizes aggregate five-hour and seven-day windows; Codex normalizes primary
and secondary rate-limit windows; Grok normalizes its aggregate shared credit allowance. Additional
provider-specific buckets are ignored. The usage adapters use private provider endpoints, so treat
snapshots as best-effort and keep failures isolated from core agent execution.

This server-side fragment reads Codex allowance using a fresh host-owned token:

```ts
import { Effect } from 'effect'
import { FetchHttpClient } from 'effect/unstable/http'
import { fetchOpenAiCodexSubscriptionUsage } from '@yolk-sdk/agent/providers/openai/codex-usage'

const snapshotEffect = fetchOpenAiCodexSubscriptionUsage(hostOAuthAccessToken, {
  requestTimeoutMs: 10_000
}).pipe(Effect.provide(FetchHttpClient.layer))
```

Use `fetchAnthropicClaudeSubscriptionUsage` for Claude. For Grok, call
`fetchXAiGrokSubscriptionUsage(token, { xAiUserId, clientVersion })`. `xAiUserId` must be the
authenticated xAI `user_id`; the adapter does not reinterpret generic `OAuthAccessToken.accountId`.
`clientVersion` must truthfully identify your host integration rather than impersonate an official
Grok release. The adapter reports its programmatic request as `headless`.

For Go, call `fetchOpenCodeGoSubscriptionUsage(Redacted.make(hostOpenCodeGoApiKey), options)` from
`@yolk-sdk/agent/providers/opencode/usage`. Unlike the OAuth adapters, it uses a Bearer API key at
`https://opencode.ai/zen/go/v1/usage`. The API key must belong to the subscription's user and workspace;
403 means the key is not entitled to Go usage. It returns `five-hour`, `seven-day`, and `monthly`
windows, preserving the provider's absolute reset times. Monthly resets are subscription-anniversary
based, not calendar-month boundaries. Missing/invalid percentages are omitted rather than filled
with zero. No browser cookies or console scraping are needed.

Shared snapshot and safe error schemas live in
`@yolk-sdk/agent/providers/subscription-usage`. Hosts own polling, credential refresh, labels,
persistence, stale-data policy, thresholds, notifications, and UI. These snapshots report
subscription allowance, not protocol `AgentUsage` token accounting.

## Test provider

```ts
import { FauxProvider, Reply } from '@yolk-sdk/agent/loop/testing'

const ProviderLayer = FauxProvider.layer(Reply.text('Hello from a deterministic test.'))
```

Use this in tests and examples only. It is not a runtime provider.

## Host responsibilities

- Store and refresh provider credentials.
- Choose models per user/session/run.
- Provide `HttpClient` and provider layers to the loop.
- Keep raw provider error bodies and secrets out of protocol events.
- Persist usage and typed provider failure metadata if your app needs it.
