---
title: Deploy with Vercel Workflows
description: Orchestrate a durable agent run with host-owned model and tool steps.
---

Use `@yolk-sdk/vercel-workflows` when a run can outlive one request or pause for human input.

## Workflow wrapper

```ts
import { createHook } from 'workflow'
import { runVercelAgentWorkflow } from '@yolk-sdk/vercel-workflows'

export async function runAgentWorkflow(input: { request: unknown; context: unknown }) {
  'use workflow'

  return await runVercelAgentWorkflow({
    input,
    runModelStep,
    runToolBatchStep,
    closeStream,
    writeError,
    awaitInput: async awaitingInput => {
      using hook = createHook<unknown>({ token: awaitingInput.hookToken })
      return await hook
    }
  })
}
```

`runModelStep`, `closeStream`, and `writeError` are app-owned `'use step'` functions.
`runToolBatchStep` may also be a step, or it may orchestrate separate tool steps and independent
child Workflow starts. Keep provider calls, tool IO, storage, and Effect work inside steps; do not
wrap a whole child loop in one parent step. See
[Independent child orchestration](../vercel-workflows/step-contracts#independent-child-orchestration).

## Code mode

Run [code mode](./code-mode#vercel-workflow) calls inside your tool-batch step, never in the
`'use workflow'` function. Executor decorators applied outside `ResolvedToolSet.execute`, such as a
Workflow stop or run-admission check, do not see nested calls; pass the same check to
`makeCodeModeTool` as `beforeNestedCall`.

## Tool steps run at least once

Vercel's queue can deliver a tool-batch step again after a crash, or while the first execution is
still running, even with the default `noWorkflowStepRetry`. Supply a durable tool ledger, scoped
to the Workflow run, where your step resolves tools:

```ts
// Fragment from your tool-batch step module. `modules`, `context`, `makeRunToolLedger`,
// `workflowRunId`, and `stepDeadlineMs` are host-owned.
import { Effect } from 'effect'
import { resolveTools } from '@yolk-sdk/agent/tools'

// Inside the 'use step' function:
const toolSet = await Effect.runPromise(
  resolveTools(modules, context, {
    ledger: { store: makeRunToolLedger(workflowRunId), deadline: () => stepDeadlineMs }
  })
)
```

`makeRunToolLedger` is your `ToolLedgerStore` (for example Postgres); see
[Ledger writes](../agent/tools-hitl#ledger-writes-for-re-executed-steps). Ledgered calls (by
default every non-`read` tool plus the built-in `subagent` tool, code mode scripts included) then
return their stored result, wait for the running execution, or report that an abandoned call may
already have been applied; they never run twice under the same ledger key. Include custom
delegation tools with `isLedgered`. Read calls still re-run. The package itself never builds tool
sets, so there is nothing to configure on `runVercelAgentWorkflow`.

## Durable stream rule

Use distinct finalization paths:

```txt
AgentEnd: durable completion commit -> AgentEnd -> closeStream
AgentError: failure commit/mapping -> AgentError -> writeError-owned close
AgentAwaitingInput: persist pending HITL -> emit pause -> release writer lock, do not close -> resume
```

Use `sequenceDurableAgentEvent` for deterministic event ids without IO,
`writeDurableAgentEvent` for id + NDJSON write, and `commitThenWriteTerminalEvent` for terminal
barriers. The helper never decides closure from an event tag. The loop closes only successful runs;
`writeError` must write the safe final error and close failure paths.
