## Connectors

`defineAction` accepts optional `access: 'read' | 'write' | 'destructive'` metadata, exported as
`ConnectorActionAccess`. `makeConnectorToolModule` uses it unless the host supplies an access
override.

Generic email's principal contracts are `EmailIncomingConnection`, `EmailImapConnection`,
`EmailSmtpConnection`, `EmailAddress`, `EmailBody`, `EmailAttachmentMetadata`,
`EmailAttachmentBase64`, `EmailAttachmentContent`, `EmailMessageSummary`, `EmailMessage`,
`EmailListMessagesInput`, `EmailListMessagesOutput`, `EmailGetMessageInput`, `EmailGetMessageOutput`,
`EmailGetAttachmentInput`, `EmailGetAttachmentRequest`, `EmailGetAttachmentOutput`,
`EmailComposeMessage`, `EmailFolderName`, `EmailDraftId`, `EmailCreateDraftInput`,
`EmailCreateDraftOutput`, `EmailSendMessageInput`, and `EmailSendMessageOutput`. `EmailClient` receives
typed list/get/get-attachment/IMAP-draft/SMTP-send requests plus a runtime
`UsernamePasswordCredential`; hosts opt into attachment retrieval through its optional
`getAttachment` method, and successful attachment output is schema-validated before exposure. The
connector exports separate `EmailIncomingCredentialSlot` and `EmailSmtpCredentialSlot` bindings and
does not bundle transport or MIME libraries.

Microsoft Outlook's principal contracts are `OutlookMessage`, `OutlookMessageIdInput`,
`OutlookListMessagesInput`, `OutlookSearchMessagesInput`, `OutlookListMessagesOutput`,
`OutlookAttachmentKind`, `OutlookAttachmentMetadata`, `OutlookAttachment`,
`OutlookListAttachmentsInput`, `OutlookListAttachmentsOutput`, `OutlookGetAttachmentInput`,
`OutlookGetAttachmentOutput`, `OutlookComposeInput`, `OutlookCreateReplyDraftInput`,
`OutlookSendMailInput`, and `OutlookSendOutput`. File attachment retrieval requires Graph's file
discriminator and valid base64 content, then exposes it as required `contentBase64`; item and
reference attachments are available only as list metadata.
`OutlookListAttachmentsOutput.attachments` decodes to an Effect `Chunk`. OAuth exports include generic,
signed-in-mailbox, shared-mailbox, and combined
slots that share `microsoft.oauth`. Action inputs use `/me` by default and accept optional `mailbox`
for `/users/{id|userPrincipalName}` Exchange Online targets. Set integration config key
`microsoftMailboxAccessModeConfigKey` (`mailboxAccessMode`) to `application` for application-token
mailbox targeting; delegated is the default.

OneDrive's principal contracts are `OneDriveItem`, `OneDriveItemIdInput`,
`OneDriveListItemsInput`, `OneDriveSearchItemsInput`, `OneDriveListItemsOutput`,
`OneDriveCreateFolderInput`, `OneDriveDeleteItemInput`, and `OneDriveDeleteItemOutput`. Inputs default
to `/me/drive`; explicit `driveId` targets `/drives/{driveId}`. Set
`microsoftOneDriveAccessModeConfigKey` (`oneDriveAccessMode`) to `delegated_all` for broad delegated
slots or `application` for application-token access; application mode requires `driveId`. Microsoft
actions use Graph v1.0 with `outlook.*` and `onedrive.*`
ids, and all scoped slots share `microsoft.oauth`.

Google Drive's principal contracts are `GoogleDriveFile`, `GoogleDriveUser`,
`GoogleDriveCapabilities`, `GoogleDriveListFilesInput`, `GoogleDriveSearchFilesInput`,
`GoogleDriveListFilesOutput`, `GoogleDriveFileIdInput`, `GoogleDriveCreateFolderInput`, and
`GoogleDriveDeleteFileOutput`. Public actions are `googleDriveListFilesAction`,
`googleDriveSearchFilesAction`, `googleDriveGetFileAction`, `googleDriveCreateFolderAction`,
`googleDriveTrashFileAction`, and `googleDriveDeleteFileAction`; `googleDriveActions` composes them
into `GoogleConnector`.

`GoogleDriveListFilesOutput.files` and repeated `GoogleDriveFile` metadata fields decode to Effect
`Chunk` values for structural equality. `GoogleDriveFileIdInput` accepts optional `resourceKey`;
parent-scoped list, search, and create inputs accept optional `parentResourceKey`. These values
produce `X-Goog-Drive-Resource-Keys` for protected link-shared files.

`GoogleDriveMetadataReadonlyOAuthCredentialSlot` requests `googleDriveMetadataReadonlyScope` for
list/search/get. `GoogleDriveFileOAuthCredentialSlot` requests `googleDriveFileScope` for folder
create, trash, and permanent delete. Both use `googleOAuthSlotId` (`google.oauth`), and
`GoogleCombinedOAuthCredentialSlot` includes both Drive scopes alongside Gmail and Calendar scopes.
Constants also include `googleDriveApiBaseUrl`, `googleDriveFolderMimeType`, and
`googleDriveFileFields`.

Google's normalized attachment and thread contracts are `GmailListAttachmentsInput`,
`GmailListAttachmentsOutput`, `GmailGetAttachmentInput`, `GmailGetAttachmentOutput`,
`GmailAttachmentBase64Url`, `GmailAttachmentBase64`, `GmailGetThreadInput`,
`GmailThreadAttachment`, `GmailThreadMessage`, and `GmailThreadOutput`.

- `GmailGetThreadInput`: required `threadId` and `format: 'full' | 'metadata' | 'minimal'`.
- `GmailThreadOutput`: required `id` and `messages`; optional `historyId`.
- `GmailThreadMessage`: required `id`, `headers`, and `attachments`; optional `threadId`, `labelIds`,
  `snippet`, `internalDate`, `body`, and `bodyMimeType`.
- `GmailThreadAttachment`: optional `partId`, `filename`, `mimeType`, `size`, `attachmentId`,
  `inline`, and `contentId`.
- `GmailListAttachmentsInput` / `GmailListAttachmentsOutput`: one `messageId` to a metadata-only
  attachment `Chunk`.
- `GmailGetAttachmentInput`: required `messageId` and `attachmentId`.
- `GmailGetAttachmentOutput`: required input IDs, non-negative integer `size`, Gmail base64url `data`,
  and standard-base64 `contentBase64`.

Non-success provider responses return `ActionResult.failure`; authorization failures use
`google_unauthorized`, while action-specific failures use `gmail_get_thread_failed`,
`gmail_list_attachments_failed`, or `gmail_get_attachment_failed`. Invalid JSON or response shape
fails with `ConnectorError { cause: 'validation_failed' }`.

See [Connectors catalog](../integrations/connectors) for action ids.
