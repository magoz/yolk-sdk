Use `@yolk-sdk/vercel-workflows` or the equivalent `@yolk-sdk/vercel-workflows/workflow` subpath for orchestration. Use `@yolk-sdk/vercel-workflows/effect` for Effect-native host route wrappers around public `workflow/api` calls, and `@yolk-sdk/vercel-workflows/testing` for host tests.

## Loop exports

| Export                    | Purpose                                             |
| ------------------------- | --------------------------------------------------- |
| `runVercelAgentWorkflow`  | orchestrate model/tool/HITL/close callbacks         |
| `defaultMaxWorkflowTurns` | default max turns, currently `500`                  |
| `noWorkflowStepRetry`     | default retry policy, `{ maxAttempts: 1 }`          |
| `retryWorkflowStep`       | retry helper for Workflow callback promises         |
| `settleWorkflowStep`      | convert a promise into `Success` / `Failure` result |

## Independent child helpers

Both helpers are exported from root and `./workflow` and run in Workflow orchestration, not inside
a single parent tool step. They do not start children or implement storage/authorization themselves.

### `orchestrateWorkflowToolBatch<Call, Result, Pause>`

Inputs:

- `calls: ReadonlyArray<Call>` and `concurrency: number`.
- `preflight: () => Promise<{ ready: true } | { ready: false; value: Pause }>`: runs once before
  dispatch; a pause fences every call.
- `execute: (call: Call, index: number) => Promise<Result>`: invokes host steps or child starts.

Returns a Promise of `{ ready: false, value }` or
`{ ready: true, results: ReadonlyArray<Result>, failures?: ReadonlyArray<{ index: number, error: unknown }> }`.
Concurrency is floored/clamped to at least one; non-finite values become one. On rejection, no new
calls are dispatched; active siblings settle and successful results retain original call order.
`ready: true` is **not** a success guarantee: inspect `failures`, retain partial progress, and map
errors to safe wire data before returning the loop callback result. Results omit failed and
undispatched calls; carry call identity in each result when mapping partial progress.

### `awaitWorkflowChild<A>`

Accepts `read: (attempt: number) => Promise<{ done: false } | { done: true; value: A }>` and
`sleep: (attempt: number) => Promise<void>`, returning `Promise<A>`. Attempts start at zero. Each
read returning `done: false` is followed by a sleep with the same index, then the next read.
Existing zero-argument callbacks remain compatible.

It alternates short durable read steps with Workflow `sleep` until `done: true`. There is no
built-in timeout or observation ceiling. Hosts can use the index for budgets/backoff and return
`{ done: true, value }` at their ceiling with a truthful still-running or unknown value; this ends
observation, not the child. Represent completed, failed, and cancelled states explicitly and keep
Stop policy host-owned. Never place a long child `returnValue` poll inside one step.

See [Bounded child observations](../vercel-workflows/step-contracts#bounded-child-observations)
for host budgeting and [Nonterminal child observations](../agent/tools-hitl#nonterminal-child-observations)
for the subagent result marker.

## Effect API exports

Import from `@yolk-sdk/vercel-workflows/effect`.

| Export                          | Purpose                                                       |
| ------------------------------- | ------------------------------------------------------------- |
| `VercelWorkflows`               | Effect service for start/read/replay/resume/cancel operations |
| `VercelWorkflowsClient`         | service shape for injected fakes/custom layers                |
| `VercelWorkflowsError`          | tagged error for public Workflow SDK failures                 |
| `VercelWorkflowsSdk`            | injectable low-level SDK dependency for tests/custom hosts    |
| `VercelWorkflowsSdkClient`      | low-level SDK dependency shape                                |
| `VercelWorkflowsSdkRun`         | low-level SDK run shape                                       |
| `VercelWorkflowFunction`        | Workflow function type accepted by `start`                    |
| `VercelWorkflowRun`             | Effect-native run handle returned by `start`/`getRun`         |
| `VercelWorkflowRunStatus`       | native Workflow run status type                               |
| `VercelWorkflowReadableOptions` | readable stream options, including `startIndex`               |
| `VercelWorkflowReadableStream`  | native Workflow readable stream type                          |
| `VercelWorkflowsOperation`      | operation names carried by `VercelWorkflowsError`             |

Layers:

| Layer                          | Purpose                                                               |
| ------------------------------ | --------------------------------------------------------------------- |
| `VercelWorkflows.layer`        | live service backed by public `workflow/api`                          |
| `VercelWorkflows.layerFromSdk` | service requiring injected `VercelWorkflowsSdk` for tests/custom SDKs |

`VercelWorkflows` methods:

| Method                         | Purpose                                                 |
| ------------------------------ | ------------------------------------------------------- |
| `start(workflow, args)`        | start a Workflow and return an Effect-native run handle |
| `getRun(runId)`                | create an Effect-native handle for an existing run      |
| `getReadable(runId, options?)` | read/replay a run stream                                |
| `tailIndex(runId)`             | read current stream tail index                          |
| `resumeHook(token, payload)`   | resume a pending Workflow hook                          |
| `cancel(runId)`                | cancel a run                                            |

`VercelWorkflowRun` members:

| Member                  | Purpose                                                       |
| ----------------------- | ------------------------------------------------------------- |
| `runId`                 | native Workflow run id                                        |
| `getReadable(options?)` | Effect-wrapped readable stream for this run                   |
| `cancel`                | Effect that cancels this run                                  |
| `status`                | Effect that resolves the native run status                    |
| `returnValue`           | Effect that resolves the typed Workflow function return value |

The API wrapper keeps Vercel's SDK underneath. It does not reimplement Vercel backend HTTP, queue, hook, or stream internals.

Every Effect operation on `VercelWorkflows` and `VercelWorkflowRun` fails with
`VercelWorkflowsError`, which carries `_tag`, `operation`, `message`, and the original `cause`.
`operation` is one of `start`, `getRun`, `getReadable`, `tailIndex`, `resumeHook`, `cancel`,
`status`, or `returnValue`. `runId` is plain data and cannot fail.

`VercelWorkflowsClient` is the Effect service shape. `VercelWorkflowsSdkClient` and
`VercelWorkflowsSdkRun` are the lower-level Promise SDK seam used by `VercelWorkflowsSdk`.

## Run result tags

| Tag                   | Meaning                             |
| --------------------- | ----------------------------------- |
| `Completed`           | closed normally                     |
| `ModelStepFailed`     | model callback failed after retries |
| `ToolBatchStepFailed` | tool callback failed after retries  |
| `AwaitInputFailed`    | HITL hook failed or missing handler |
| `CloseStreamFailed`   | close callback failed               |
| `MaxTurnsExceeded`    | exceeded `maxTurns`                 |

## Terminal helper results

| Tag                      | Meaning                                                 |
| ------------------------ | ------------------------------------------------------- |
| `Committed`              | commit succeeded and terminal write succeeded           |
| `CommitFailed`           | commit failed and commit-error terminal write succeeded |
| `TerminalWriteFailed`    | commit succeeded but terminal write failed              |
| `CommitErrorWriteFailed` | commit failed and commit-error terminal write failed    |

The terminal helper does not close streams or infer finality from event tags. Successful
`AgentEnd` closes through `closeStream`; failure `AgentError` closes through `writeError`. Release
the writer lock without final-closing resumable `AgentAwaitingInput`.
