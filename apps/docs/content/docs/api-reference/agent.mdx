`@yolk-sdk/agent/tools`

| Export                           | Purpose                                                   |
| -------------------------------- | --------------------------------------------------------- |
| `makeTool`                       | schema-backed tool registration                           |
| `resolveTools`                   | filter/merge modules into model-visible defs and executor |
| `makeToolExecutorLayer`          | provide resolved executor as `ToolExecutor`               |
| `EmptyToolParams`                | no-arg tool schema                                        |
| `ToolAccess`                     | `read`, `write`, `destructive`                            |
| `makeQuestionToolModule`         | built-in question HITL tool                               |
| `makeNonRecursiveTaskToolModule` | subagent task tool without recursion                      |
| `TaskRuntimeSelectionOptions`    | host-advertised subagent model and reasoning choices      |
| `TaskModelDefinition`            | model id and model-visible selection guidance             |
| `TaskReasoningEffortDefinition`  | reasoning effort and model-visible selection guidance     |
| `modelVisibleToolError`          | recoverable error visible to model                        |

Task/question helpers: `makeTaskToolModule`, `makeTaskToolDef`, `makeTaskToolResult`, `taskToolName`, `makeQuestionToolDef`, `questionToolName`.

Configure `models` and `reasoningEfforts` on a task tool module to expose validated optional
`model` and `reasoning_effort` parameters to the parent agent. Omission means the host should
inherit its current runtime setting. Hosts remain responsible for provider credentials, capability
checks, and constructing the selected child runtime. Pass the effective effort to
`makeTaskToolResult` as `reasoningEffort` to include `reasoning_effort` in structured result
metadata.

The public task types are:

```ts
// TypeScript fragments

type TaskSubagentDefinition = {
  readonly name: string
  readonly description: string
}

type TaskModelDefinition = {
  readonly id: string
  readonly description: string
}

type TaskReasoningEffortDefinition = {
  readonly value: AgentReasoningEffort
  readonly description: string
}

type TaskRuntimeSelectionOptions = {
  readonly models?: ReadonlyArray<TaskModelDefinition>
  readonly reasoningEfforts?: ReadonlyArray<TaskReasoningEffortDefinition>
}

type TaskSubagentContext = {
  readonly subagent?: boolean
}

type TaskToolParams = {
  readonly description: string
  readonly prompt: string
  readonly subagent_type: string
  readonly model?: string
  readonly reasoning_effort?: AgentReasoningEffort
}

type TaskExecutionInput<Context> = {
  readonly call: ToolCall
  readonly context: Context
  readonly params: TaskToolParams
}

type TaskToolOptions<Context> = TaskRuntimeSelectionOptions & {
  readonly subagents: ReadonlyArray<TaskSubagentDefinition>
  readonly isEnabled?: (
    context: Context
  ) => Effect.Effect<boolean, ToolRegistryError>
  readonly execute: (
    input: TaskExecutionInput<Context>
  ) => Effect.Effect<ToolResult, ToolError>
}

type TaskToolResultInput = {
  readonly callId: string
  readonly output: string
  readonly subagentType: string
  readonly description: string
  readonly subagentRunId: string
  readonly startedAtMs: number
  readonly endedAtMs: number
  readonly model: string
  readonly reasoningEffort?: AgentReasoningEffort
  readonly isError?: boolean
}
```

`AgentReasoningEffort` accepts `minimal`, `low`, `medium`, `high`, or `xhigh`. Model IDs are
host-owned opaque strings and are not normalized by the task tool.

Task helper signatures:

| Helper | Signature and return |
| ------ | -------------------- |
| `makeTaskToolDef` | `(subagents: ReadonlyArray<TaskSubagentDefinition>, runtimeSelections?: TaskRuntimeSelectionOptions) => ToolDef` |
| `makeTaskToolRegistration` | `<Context>(options: TaskToolOptions<Context>) => ToolRegistration<Context>` |
| `makeTaskToolModule` | `<Context>(options: TaskToolOptions<Context>) => ToolModule<Context>` |
| `makeNonRecursiveTaskToolModule` | `<Context extends TaskSubagentContext>(options: TaskToolOptions<Context>) => ToolModule<Context>` |
| `makeTaskToolResult` | `(input: TaskToolResultInput) => ToolResult` |
| `formatTaskResult` | `(output: string) => string` |
| `subagentResultText` | `(events: ReadonlyArray<AgentEvent>) => string` |
| `taskSubagentRunId` | `(parentToolCallId: string) => string` |
| `taskToolName` | `"task"` |

Selections outside the configured enums, empty required strings, and unknown subagent types return
model-visible validation results before host execution. Their structured error reason is
`validation`. The host `execute` callback may fail with `ToolError`. `makeTaskToolResult` includes
`reasoning_effort` only when `reasoningEffort` is provided.

`TokenEstimateOptions.countTextTokens` accepts a synchronous host tokenizer for message text,
reasoning, and host tool-call ids/names. Media, message overhead, non-message request input, and
vendor framing remain outside that callback. Window planners and transformers also accept a
whole-transcript `estimateTokens`; use one estimator consistently and keep a safety margin.

Checkpoint predicates detect the package's open/close marker strings; they are not structural
parsers. Use them only on host-produced projected context, not arbitrary user-authored messages.

Provider output limits are required and host-owned:

- `OpenAiProviderConfig.maxCompletionTokens` becomes vendor `max_completion_tokens`.
- `OpenAiCodexProviderConfig.maxOutputTokens` remains required host configuration, but ChatGPT
  subscription Codex requests omit unsupported vendor `max_output_tokens`.
- `AnthropicClaudeProviderConfig.maxTokens` becomes vendor `max_tokens`.
- `OpenAiProviderLayer` reads `OPENAI_API_KEY` and integer
  `OPENAI_MAX_COMPLETION_TOKENS` through Effect Config.

The three public request lowerers require a second configuration argument containing the matching
limit. Yolk does not infer limits from model ids.
