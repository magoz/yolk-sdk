Subagent/question helpers: `makeSubagentToolModule`, `makeSubagentToolDef`, `makeSubagentToolResult`, `subagentToolName`, `makeQuestionToolDef`, `questionToolName`.

Configure `models` and `reasoningEfforts` on a subagent tool module to expose validated optional
`model` and `reasoning_effort` parameters to the parent agent. Omission means the host should
inherit its current runtime setting. Hosts remain responsible for provider credentials, capability
checks, constructing the selected child runtime, and context/tool-result budgeting. Pass effective
runtime metadata to `makeSubagentToolResult`; optional `reasoningEffort`, `usage`, `turns`, and typed
`error` fields are added to structured result metadata.

The public subagent types are:

```ts
// TypeScript fragments

type SubagentDefinition = {
  readonly name: string
  readonly description: string
}

type SubagentModelDefinition = {
  readonly id: string
  readonly description: string
}

type SubagentReasoningEffortDefinition = {
  readonly value: AgentReasoningEffort
  readonly description: string
}

type SubagentRuntimeSelectionOptions = {
  readonly models?: ReadonlyArray<SubagentModelDefinition>
  readonly reasoningEfforts?: ReadonlyArray<SubagentReasoningEffortDefinition>
}

type SubagentContext = {
  readonly subagent?: boolean
}

type SubagentToolParams = {
  readonly description: string
  readonly prompt: string
  readonly subagent_type: string
  readonly model?: string
  readonly reasoning_effort?: AgentReasoningEffort
}

type SubagentExecutionInput<Context> = {
  readonly call: ToolCall
  readonly context: Context
  readonly params: SubagentToolParams
}

type SubagentToolOptions<Context> = SubagentRuntimeSelectionOptions & {
  readonly subagents: ReadonlyArray<SubagentDefinition>
  readonly isEnabled?: (context: Context) => Effect.Effect<boolean, ToolRegistryError>
  readonly execute: (input: SubagentExecutionInput<Context>) => Effect.Effect<ToolResult, ToolError>
}

type SubagentRunError = {
  readonly code: AgentErrorCode
  readonly message: string
  readonly retryable: boolean
  readonly provider?: ProviderErrorInfo
}

type SubagentRunStatus = 'completed' | 'awaiting_input' | 'error'

type SubagentRunResult = {
  readonly status: SubagentRunStatus
  readonly text: string
  readonly usage?: AgentUsage
  readonly turns?: number
  readonly requests?: ReadonlyArray<HitlRequest>
  readonly error?: SubagentRunError
}

type SubagentToolResultInput = {
  readonly callId: string
  readonly output: string
  readonly subagentType: string
  readonly description: string
  readonly subagentRunId: string
  readonly startedAtMs: number
  readonly endedAtMs: number
  readonly model: string
  readonly reasoningEffort?: AgentReasoningEffort
  readonly usage?: AgentUsage
  readonly turns?: number
  readonly status?: SubagentRunStatus
  readonly requests?: ReadonlyArray<HitlRequest>
  readonly error?: SubagentRunError
  readonly isError?: boolean
}
```

`AgentReasoningEffort` accepts `minimal`, `low`, `medium`, `high`, or `xhigh`. Model IDs are
host-owned opaque strings and are not normalized by the subagent tool.

Subagent helper signatures:

| Helper                               | Signature and return                                                                                             |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `makeSubagentToolDef`                | `(subagents: ReadonlyArray<SubagentDefinition>, runtimeSelections?: SubagentRuntimeSelectionOptions) => ToolDef` |
| `makeSubagentToolRegistration`       | `<Context>(options: SubagentToolOptions<Context>) => ToolRegistration<Context>`                                  |
| `makeSubagentToolModule`             | `<Context>(options: SubagentToolOptions<Context>) => ToolModule<Context>`                                        |
| `makeNonRecursiveSubagentToolModule` | `<Context extends SubagentContext>(options: SubagentToolOptions<Context>) => ToolModule<Context>`                |
| `makeSubagentToolResult`             | `(input: SubagentToolResultInput) => ToolResult`                                                                 |
| `formatSubagentResult`               | `(output: string) => string`                                                                                     |
| `subagentResultFromEvents`           | `(events: ReadonlyArray<AgentEvent>) => SubagentRunResult`                                                       |
| `subagentResultText`                 | `(events: ReadonlyArray<AgentEvent>) => string`                                                                  |
| `subagentUsageFromToolResult`        | `(result: ToolResult) => AgentUsage \| undefined`                                                                |
| `subagentToolRunId`                  | `(parentToolCallId: string) => string`                                                                           |
| `subagentToolName`                   | `"subagent"`                                                                                                     |

Selections outside the configured enums, empty required strings, and unknown subagent types return
model-visible validation results before host execution. Their structured error reason is
`validation`. The host `execute` callback may fail with `ToolError`. `makeSubagentToolResult` includes
optional fields only when provided. `subagentResultFromEvents` extracts terminal text and
usage/turns from `AgentEnd` or `AgentAwaitingInput`, preserves awaiting HITL requests/status, or
returns typed `AgentError` metadata. `subagentResultText` remains the compatibility text-only helper. Use
`subagentUsageFromToolResult` to recover child usage from a structured result for cumulative host
accounting.

## Compaction

`@yolk-sdk/agent/compaction`

`makeContextBudget` accepts an optional `maxInputTokens` cap for provider- or endpoint-specific
input ceilings below a model's total context window. `usableInputTokens` is the smaller of this cap
and `contextWindowTokens - reservedOutputTokens`; omit it when the endpoint has no separate input
ceiling.

| Export                                                                                                       | Purpose                                  |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |

| `estimateAgentMessageTokens`, `estimateAgentMessagesTokens`, `estimateContentTokens`, `estimateTextTokens`   | token estimation helpers                 |
| `TokenEstimateOptions`, `MessageTokenEstimator`, `TranscriptTokenEstimator`                                  | host tokenizer and estimator contracts   |
| `planWindowCompaction`, `applyCompactionPlan`, `compactWindowMessages`                                       | window compaction helpers                |
| `makeWindowCompactionTransformer`                                                                            | `ContextTransformer` layer helper        |

| `isCompactionCheckpointText`, `isCompactionCheckpointMessage`                                                | host-controlled marker predicates        |
| `formatAgentMessageForCompaction`, `formatAgentMessagesForCompaction`                                        | rich transcript summary-source formatter |
| `CompactionMessageFormatOptions`                                                                             | reasoning/tool formatting controls       |
| `compactionSummarySourceMessages`, `dropLeadingCompactionCheckpointMessage`                                  | repeated-summary helper                  |
| `makeContextOverflowRetryProvider`                                                                           | one-shot provider overflow retry wrapper |
| `ContextOverflowRetryCompactionResult`, `ContextOverflowRetryCompactor`, `ContextOverflowRetryProviderInput` | retry wrapper contracts                  |

`TokenEstimateOptions.countTextTokens` accepts a synchronous host tokenizer for message text,
reasoning, and host tool-call ids/names. Media, message overhead, non-message request input, and
vendor framing remain outside that callback. Window planners and transformers also accept a
whole-transcript `estimateTokens`; use one estimator consistently and keep a safety margin.

Checkpoint predicates detect the package's open/close marker strings; they are not structural
parsers. Use them only on host-produced projected context, not arbitrary user-authored messages.

Subscription-usage fetchers require a matching fresh `OAuthAccessToken` and `HttpClient.HttpClient`.
All accept an optional positive `requestTimeoutMs`; endpoint origins stay fixed. Grok additionally
requires explicit `xAiUserId` and truthful host `clientVersion` options and does not derive the xAI
identity from generic token `accountId`. With `FetchHttpClient.layer`, redirects are manual and
rejected. A custom `HttpClient` must not follow redirects for these credential-bearing requests.
Returned `windows` is an immutable Effect `Chunk`
whose entries have semantic `id`, `usedPercent`, and optional `resetsAt`, `resetsAfterSeconds`, and
`windowDurationMinutes` fields. HTTP, decoding,
and recognized malformed-field failures use sanitized `ProviderSubscriptionUsageError` variants;
unrecognized or absent buckets may produce an empty snapshot. Raw response bodies are not retained.

Provider output limits are host-owned where supported:

- `OpenAiProviderConfig.maxCompletionTokens` becomes vendor `max_completion_tokens`.
- `VercelAiGatewayProviderConfig.maxCompletionTokens` becomes Gateway `max_tokens`; optional
  `fallbackModels` and `routing` become Gateway request extensions.
- ChatGPT subscription Codex rejects vendor `max_output_tokens`; its optional deprecated
  `maxOutputTokens` compatibility field is ignored.
- `AnthropicClaudeProviderConfig.maxTokens` becomes vendor `max_tokens`.
- `XAiGrokProviderConfig.maxOutputTokens` becomes vendor `max_output_tokens` on the xAI CLI proxy.
- `XAiGrokProviderConfig.clientVersion` is required and sent as `x-grok-client-version`; the xAI
  CLI proxy version-gates requests and rejects missing or outdated client versions with HTTP 426.
- `OpenAiProviderLayer` reads `OPENAI_API_KEY` and integer
  `OPENAI_MAX_COMPLETION_TOKENS` through Effect Config.
- `VercelAiGatewayProviderLayer` reads `AI_GATEWAY_API_KEY`, falls back to `VERCEL_OIDC_TOKEN`, and
  requires integer `AI_GATEWAY_MAX_COMPLETION_TOKENS`.

`toOpenAiRequestBody`, `toAnthropicClaudeRequestBody`, and `toXAiGrokRequestBody` require matching
limit configuration. `toOpenAiCodexRequestBody` accepts the optional ignored compatibility field but
sends no output limit. Yolk does not infer limits from model ids. Generic OpenAI-compatible hosts may
select `OpenAiProviderConfig.completionTokenField`, add endpoint extensions through `extraBody`, and
set `providerIdentity` for accurate safe error metadata; canonical request fields and required HTTP
headers take precedence.
