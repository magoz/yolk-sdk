> **Experimental.** `@yolk-sdk/conformance` may change in any canary release. It is new after
> `0.1.0-canary.95`; keep it on the same lockstep version as the other public packages.

`@yolk-sdk/conformance` records real HTTP exchanges with outside services, replays them in tests
offline (fail closed), and injects wire faults. It also defines conformance cases, each proving one
claim about how a service really behaves on the wire, and a runner that gates cases by safety and
reports. It depends only on `effect` and never performs
network I/O itself: for live recording, your host supplies the real `HttpClient`.

There is no root export. Import an explicit subpath.

## Fixture

`@yolk-sdk/conformance/fixture`

| Export                                                                                                   | Purpose                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WireFixture`                                                                                            | Schema and type: `id`, `caseId`, `evidence`, `recordedAt` (`YYYY-MM-DD`), `account`, `endpoint`, `model?`, `note?`, `exchanges`                                                                                                                                                                                           |
| `WireExchange`, `WireRequest`, `WireResponse`                                                            | One request (method, absolute URL, allowlisted headers, JSON or text body) and its response                                                                                                                                                                                                                               |
| `WireBodyResponse`, `WireTextBodyResponse`, `WireBase64BodyResponse`                                     | Whole body: exactly one of `body` (valid UTF-8 string) or `bodyBase64` (exact bytes, for example a PDF)                                                                                                                                                                                                                   |
| `WireStreamResponse`, `WireChunk`                                                                        | Streamed `chunks` with original boundaries; each entry is a string (valid UTF-8 on its own, empty chunks `""`) or `{ base64 }` with the exact bytes                                                                                                                                                                       |
| `WireFixtureEvidence`, `WireHeaders`                                                                     | `verified` / `unverified`; lowercase header record                                                                                                                                                                                                                                                                        |
| `decodeWireFixture`                                                                                      | Decode unknown input (for example a JSON file) into a fixture                                                                                                                                                                                                                                                             |
| `isWireStreamResponse`, `isWireBase64BodyResponse`                                                       | Narrow a response to the streamed or base64 body shape                                                                                                                                                                                                                                                                    |
| `fixtureAgeDays`, `isFixtureStale`                                                                       | Whole UTC days since `recordedAt`; stale after `maxAgeDays` (default 30)                                                                                                                                                                                                                                                  |
| `PortFixture`, `PortFailure`, `decodePortFixture`                                                        | One non-HTTP port call: `id`, `port`, `method`, credential-free JSON `request`, exactly one of `response` or `failure` (`expected` / `error`), `observed?`, `note?`                                                                                                                                                       |
| `redactPortPayload`, `scanPortFixtureForSecrets`                                                         | Drop credential fields (AWS-style `accessKeyId` / `secretAccessKey` / `sessionToken` included) from a port payload; scan a port fixture (token patterns, credential fields, any non-null `credential(s)`, credential query parameters inside JSON strings, `note`, and `failure.message`)                                 |
| `PortValueFixture`, `PortFailureFixture`, `isPortFixture`, `isPortFailureFixture`, `isPortCredentialKey` | The two port fixture branches, their narrowing helpers, and the credential-key predicate `redactPortPayload` uses                                                                                                                                                                                                         |
| `ConformanceFixture`, `conformanceFixtureEvidence`                                                       | `WireFixture \| PortFixture`; evidence and date (a port fixture is `verified` only with `observed`)                                                                                                                                                                                                                       |
| `scanFixtureForSecrets`, `FixtureSecretIssue`                                                            | Pure scan for credential headers, bearer tokens, API-key prefixes, JWTs, credential query/form params and JSON fields                                                                                                                                                                                                     |
| `syntheticPortCredentialParams`                                                                          | Frozen exact synthetic placeholders, keyed by parameter name (SigV4 `x-amz-signature`, `x-amz-credential`): the only values `scanPortFixtureForSecrets` accepts, compared with the whole raw value (up to `&`, `#`, whitespace, quotes, `<`, `>`; never `?`) after percent-decoding; `scanFixtureForSecrets` accepts none |

Fixtures must contain synthetic or scrubbed data only. The scan covers metadata strings, URLs,
headers, request and response bodies (including decodable `bodyBase64` text), each chunk, and the
reassembled stream, so a secret split across chunks is still found. JSON bodies and SSE `data:`
payloads get the credential-field scan (`access_token`, `client_secret`, `password`, `token`, ...);
numeric usage counters such as `max_tokens` are not flagged. SSE framing with CRLF, LF, or bare CR
line endings is recognized. The scan errs toward flagging: a field named exactly `token` (for
example an OpenAI `logprobs` entry) is flagged, so avoid recording logprobs. It reports locations,
never secret values, and is a safety net rather than a guarantee.

A `PortFixture` records one call through a host port that is not HTTP, such as the generic
`EmailClient`. Without `observed` it is a synthetic placeholder (`unverified`, no date); with
`observed: { account, date }` it is `verified` as of that date. Record requests through
`redactPortPayload` and scan them with `scanPortFixtureForSecrets`, which also flags credential
query parameters inside any JSON string, the note, or the failure message (a signed URL a port
answered, such as an S3 presigned URL's `X-Amz-Signature`). Every `name=` is found and judged on its
own. The only exemption: the raw value, up to a structural boundary (`&`, `#`, whitespace, `"`,
`<`, `>`, or the end; a raw `?` or `'` and encoded delimiters such as `%3F` or `%26` stay inside it),
percent-decoded, exactly equals that parameter's entry in `syntheticPortCredentialParams`. It does
not see parameters with escaped names (`&amp;` before them, percent-encoded names), which port
owners check themselves (the R2 port cases ship `findR2PortFixtureSecrets`). Replaying port fixtures
belongs to the port owner (for example `makeEmailReplayBackend`); the runner accepts both fixture
kinds for its fixture warnings.

## Replay

`@yolk-sdk/conformance/replay`

| Export                                       | Purpose                                                                                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReplayHttpClient.layer(fixtures, options?)` | `Layer<HttpClient.HttpClient \| ReplayLedger>` with fresh state per build                                                                               |
| `makeReplayHttpClient`                       | Effect returning `{ client, ledger }` for manual wiring                                                                                                 |
| `ReplayLedger.entries`, `ReplayLedgerEntry`  | Every request: method, URL, redacted headers, body text/JSON, attempt, match outcome (`matched`, `injected`, `unmatched`, `invalid`), applied fault tag |
| `ReplayLedger.remaining`                     | Recorded exchanges (`fixtureId`, `exchangeIndex`) not consumed yet, in fixture order                                                                    |
| `WireFault`                                  | `StatusOnAttempt`, `FailAfterChunks`, `TruncateAfterChunks`, `HoldAfterChunks` constructors                                                             |
| `WireTransportFault`                         | Cause attached to a body stream failed by `FailAfterChunks`                                                                                             |
| `WireReplayInvalid`                          | Cause of the `HttpClientError` for a matched exchange that cannot be replayed as requested                                                              |

Requests match by method and normalized absolute URL (hash removed, query parameters sorted). Each
exchange is consumed once, in recorded order per method and URL. Unknown requests fail with an
`HttpClientError` whose message names the method and URL only, and are still recorded in the
ledger as `unmatched`; faults never answer them, so `StatusOnAttempt` fires only when an
unconsumed recorded exchange exists for the method and URL. Replay emits the exact recorded bytes:
one `Uint8Array` per recorded chunk (including empty ones), each produced only when pulled, and
`bodyBase64` as the original bytes. A fault `match.url` matches exactly, or as a prefix when it
ends with `*`.

A chunk fault that cannot take effect fails the request with an `HttpClientError` whose cause is
`WireReplayInvalid`, recorded in the ledger as `invalid` without a fault tag: any chunk fault
matched against a whole-body response, `TruncateAfterChunks` or `HoldAfterChunks` with `chunks` at
or beyond the recorded chunk count, or `FailAfterChunks` with `chunks` beyond it. The error reason
is a `TransportError`, which generic transient-retry policies retry; when a test runs through a
retrying client, also assert the ledger has no `invalid` outcome.

```ts
import { Effect } from 'effect'
import { ReplayHttpClient, ReplayLedger, WireFault } from '@yolk-sdk/conformance/replay'

const replayLayer = ReplayHttpClient.layer([hostFixture], {
  faults: [WireFault.StatusOnAttempt({ attempt: 1, status: 429, headers: { 'retry-after': '2' } })]
})

const ledgerEntries = Effect.gen(function* () {
  const ledger = yield* ReplayLedger
  return yield* ledger.entries
})
```

`hostFixture` is a placeholder for your own `WireFixture`. Provide `replayLayer` below the code
under test, for example a provider layer.

## Record

`@yolk-sdk/conformance/record`

| Export                                                                                       | Purpose                                                                                                             |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `WireRecorder.layer(options?)`                                                               | Wraps the `HttpClient` already in context; provides the recording client and `WireRecorder`                         |
| `makeRecordingHttpClient`                                                                    | Effect returning `{ client, recorder }` around a given client                                                       |
| `WireRecorderApi.drain`                                                                      | Take recorded exchanges; fails with `WireRecordingIncomplete` if a request failed or was unread                     |
| `makeWireFixture`                                                                            | Validate a fixture; fails with `WireFixtureInvalid` on schema errors or `WireFixtureSecretsFound` on any scan issue |
| `WireFixtureInvalid`, `WireFixtureSecretsFound`, `WireRecordingIncomplete`                   | Typed errors from `makeWireFixture` and `drain`                                                                     |
| `defaultRecordedRequestHeaders`, `defaultRecordedResponseHeaders`, `defaultStreamMediaTypes` | Allowlist defaults                                                                                                  |

The recorder keeps `content-type` and `accept` request headers and `content-type`, `retry-after`,
`retry-after-ms`, and rate-limit response headers by default. Credential headers such as
`authorization`, `cookie`, `set-cookie`, and token/key-bearing names such as `x-auth-token`,
`private-token`, or `x-*-key` are always dropped. `text/event-stream` responses are teed chunk by
chunk without changing what the caller receives; each chunk is recorded standalone as text when
valid UTF-8, otherwise as `{ base64 }`. Other bodies are recorded as `body` or `bodyBase64`. A
request still pending when `drain` runs is reported by that drain and then dropped; it never lands
in a later drain.

## Case

`@yolk-sdk/conformance/case`

| Export                                            | Purpose                                                                                                                                               |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ConformanceCase<E, R>`                           | `id`, `title?`, `safety`, `docs` (what the docs claim), `wire` (what the wire does), `observed?`, `fixtures` (fixture ids), `run: Effect<void, E, R>` |
| `defineConformanceCase`                           | Validates case metadata; throws `ConformanceCaseInvalid` for an invalid definition                                                                    |
| `ConformanceSafety`                               | Schema and type: `read`, `write-reversible` (leaves the account as it found it), `write-irreversible` (never automated)                               |
| `ConformanceObservation`                          | Schema and type: `{ account, date }`, a synthetic account label and `YYYY-MM-DD`; absent on a case means unverified                                   |
| `ConformanceCaseId`                               | Schema: dotted lower-case id, two or more segments                                                                                                    |
| `expectConformance(condition, message, details?)` | Fails with `ConformanceMismatch` when `condition` is false                                                                                            |
| `expectEqual(actual, expected, message)`          | Structural JSON equality (`Equal.equals`); fails with `ConformanceMismatch` carrying both values                                                      |
| `ConformanceMismatch`, `ConformanceCaseInvalid`   | Typed mismatch (`message`, optional JSON `expected` / `actual`); invalid-definition error                                                             |

## Runner

`@yolk-sdk/conformance/runner`

| Export                                               | Purpose                                                                                                                                                 |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runConformance(cases, options)`                     | `Effect<ConformanceReport, never, LR>`; runs allowed cases one at a time by default, each with a freshly built `options.layer(case)`                    |
| `ConformanceRunOptions`                              | `target`, `layer`, `fixtures?` (wire or port), `now?` (default `Clock`), `maxFixtureAgeDays?` (default 30), `concurrency?` (default 1)                  |
| `ConformanceTarget`                                  | `replay`, `in-process`, `emulated`, or `live` with `account`, `allowWrites?` (`none` default / `reversible`), and `allowIrreversible?` (exact ids)      |
| `conformanceSkipReason`                              | The safety policy: `undefined` (runs), `writes-not-allowed`, or `manual-only`                                                                           |
| `conformanceCaseWarnings`, `ConformanceWarning`      | `unverified-case`, `stale-observation`, `unverified-fixture`, `stale-fixture`, `missing-fixture`                                                        |
| `ConformanceReport`, `ConformanceCaseResult`         | Target, `startedAt`, per-case `status` / `skipReason` / sanitized `failure` / `durationMs` / `warnings`, and a summary                                  |
| `formatConformanceReport`, `conformanceReportFailed` | Plain-text report (one line per case plus a summary, no colors); true when any case failed                                                              |
| `sanitizeConformanceMessage`                         | Best-effort message sanitizer the runner applies to non-mismatch failures (credentials and credential header lines redacted, JSON spans elided, capped) |
| `ConformanceCaseRequirements`                        | Requirements of a case type (or union); what `layer` must provide                                                                                       |

| Target                             | `read` | `write-reversible`                                                    | `write-irreversible`                                                    |
| ---------------------------------- | ------ | --------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `replay`, `in-process`, `emulated` | runs   | runs                                                                  | runs                                                                    |
| `live`                             | runs   | runs only with `allowWrites: 'reversible'`, else `writes-not-allowed` | runs only if its exact id is in `allowIrreversible`, else `manual-only` |

Skipped cases never build their layer. Each running case calls `options.layer(case)` and builds
the result fresh (fresh memo map and scope), so state a layer allocates when it is built (replay
consumption, ledgers, emulator state) never leaks between cases. Layers must allocate their
mutable state when built: a service captured in a shared value (one `Layer.succeed(service,
instance)` reused across cases) or provided by the caller's environment is not rebuilt and stays
shared. Failures, layer build failures, a throwing `layer` factory, and defects become `failed`
results; interruption still interrupts the run.

Failure reports carry an identifier-like, non-credential-shaped error tag (other tags are omitted)
and a message, never request bodies, headers, or mismatch `expected` / `actual` details. A
`ConformanceMismatch` keeps its case-authored message with credential patterns redacted. Every
other message is sanitized best-effort by `sanitizeConformanceMessage`: credential patterns shared
with the fixture secret scan and credential header lines (`Cookie:`, `X-Api-Key:`,
`Proxy-Authorization:`, ...) are redacted, JSON-looking spans become `[json]`, whitespace is
collapsed, and the length is capped at 300 characters. Hosts should still keep secrets out of error
messages.

Live targets omit all fixture-level warnings (`unverified-fixture`, `stale-fixture`,
`missing-fixture`) because fixtures are not used live; case-level warnings always apply. On other
targets fixture warnings need `fixtures`.

```ts
import { Effect } from 'effect'
import { ReplayHttpClient } from '@yolk-sdk/conformance/replay'
import { formatConformanceReport, runConformance } from '@yolk-sdk/conformance/runner'

const report = runConformance(hostCases, {
  target: { kind: 'replay' },
  fixtures: hostFixtures,
  layer: testCase =>
    ReplayHttpClient.layer(hostFixtures.filter(fixture => testCase.fixtures.includes(fixture.id)))
}).pipe(Effect.map(formatConformanceReport))
```

`hostCases` and `hostFixtures` are placeholders for your own cases and fixtures.

## Connector conformance

> **Experimental.** Conformance/testing only.

`@yolk-sdk/connectors/conformance` provides the connector ports from an Effect `HttpClient`, so
connector cases run the real connector actions over replay, an emulator, or a host's live client:

| Export                                                    | Purpose                                                                                                                                                                                                                     |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `connectorHttpClientFromEffectHttpClientLayer`            | `ConnectorHttpClient` over the `HttpClient` in context; keeps method, URL, headers, string body, content type, status, and body text                                                                                        |
| `connectorBinaryHttpClientFromEffectHttpClientLayer`      | GET-only `ConnectorBinaryHttpClient`; buffers, then fails oversize 200s (`response_too_large`) and truncates error bodies                                                                                                   |
| `connectorBinaryWriteHttpClientFromEffectHttpClientLayer` | `ConnectorBinaryWriteHttpClient` with `uploadSession`: POST/PUT bytes, and PUT ranges / empty DELETE cancellation to pre-authenticated session URLs; refuses bad requests and credential headers on sessions before sending |
| `connectorHttpClientsFromEffectHttpClientLayer`           | All three bridges                                                                                                                                                                                                           |
| `ConformanceCleanupReporter`                              | `Context.Reference` receiving cleanup problems a write case raises while being interrupted; default `Effect.logWarning`; the Dropbox, Notion, Todoist, and Telegram live runners print WARN lines                           |
| `staticCredentialResolverLayer(credentials)`              | `CredentialResolver` returning one `RuntimeCredential` for every slot, or credentials keyed by slot id (missing: `credential_missing`)                                                                                      |

These bridges are **not production adapters**. They enforce no streamed byte limits, redirect,
DNS/IP, timeout, or TLS policy; binary limits are checked only after buffering. `redirect: 'manual'`
and `credentials: 'omit'` are forwarded as `FetchHttpClient.RequestInit` options, and transport
failures become code-only errors without URLs, headers, or bodies. The static resolver ignores
scopes and never refreshes; hosts own real credential storage.

`@yolk-sdk/connectors/fortnox/conformance` exports seven Fortnox cases (`fortnoxConformanceCases`),
their synthetic fixtures (`fortnoxConformanceFixtures`, `evidence: 'unverified'`), and the seeds they
replay with (`fortnoxConformanceFixtureSeeds`). Cases need the connector ports plus
`FortnoxConformanceConfig`, which holds seed identities in a Fortnox developer test company. A
missing seed fails the case with a `precondition:` mismatch before any request. None of the cases is
observed live yet, so reports warn `unverified-case`.

The row and customer mutation cases restore what they change, verify the restore by reading back,
and fail with `FortnoxConformanceRestoreFailed` instead of hiding a failed restore. The rejection
case restores nothing: it only confirms that the customer is absent before its write, and reports
any invoice Fortnox unexpectedly creates for manual cancellation. See
[Fortnox conformance cases](../connectors/fortnox#conformance-cases) for the case table, seeds, and
claims.

`@yolk-sdk/connectors/microsoft/conformance` exports eleven Microsoft Graph cases
(`microsoftConformanceCases`), their synthetic fixtures (`microsoftConformanceFixtures`), and the
seeds they replay with (`microsoftConformanceFixtureSeeds`). Cases need `ConnectorHttpClient`,
`CredentialResolver`, and `MicrosoftConformanceConfig` (seed identities in a Microsoft 365 practice
tenant). Outlook and OneDrive cases run the real connector actions. The connector has no calendar

(`r2ConformanceCases`), their synthetic `PortFixture`s (`r2ConformanceFixtures`), and the seeds they
replay with (`r2ConformanceFixtureSeeds`). The connector never talks to R2 itself: the cases run

When a case is interrupted, the run no longer produces a report, and no further case starts. So
Dropbox, Notion, Todoist, GitHub, and Microsoft write cases, the Fortnox row and customer mutation
cases, the Telegram send, and the R2 puts also hand a cleanup problem raised during the interruption
(a failed cleanup, or a create, send, or put whose outcome is unknown) to `ConformanceCleanupReporter`
from `@yolk-sdk/connectors/conformance`, a `Context.Reference` whose default logs it with
`Effect.logWarning`. The Fortnox rejection case and the Fortnox email send do not report. With the
Effect version this repository pins, such a run ends with that failure itself (no Interrupt in the
cause), and a run whose cleanup succeeded ends as a plain interruption; drills in the connector
tests pin both, so an Effect upgrade that changes this fails visibly. The Dropbox, Notion, Todoist,
and Telegram live runners print reported problems to stderr as WARN lines. Their first
SIGINT/SIGTERM interrupts the run fiber so the cleanup is attempted; duplicates within a second (one
Ctrl-C reaches every process of the foreground group, and the wrappers relay it) are ignored, and a
later signal exits at once. Only after an interrupt-only exit (code 130) does the read-only leftover
lookup run again and list what is still present; a run that ends with a cleanup failure exits 1 with
that failure's message. Run live runs as `pnpm conformance:<provider>` or with `tsx` directly:
`pnpm exec tsx` returns to the prompt at once on Ctrl-C (observed), so later output prints after the
prompt, `$?` is pnpm's own code, and the runner is then stopped with `kill -TERM <pid>` (the
first-signal message prints the pid).
