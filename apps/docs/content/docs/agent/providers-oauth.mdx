Provider subpaths translate Yolk messages/tools into vendor requests and normalize stream events back into Yolk protocol.

For the current provider catalog and setup snippets, see [Model providers](../integrations/model-providers).

## Provide fresh credentials at runtime

Provider packages may model vendor auth mechanics, but hosts own:

- refresh token storage
- encryption and rotation
- broker routes
- OAuth callbacks
- account linking
- model-specific output-token limits
- policy and audit

Give provider layers fresh access tokens at execution time. Do not store raw secrets in protocol messages, annotations, tool results, or docs examples.

Vercel AI Gateway accepts either an AI Gateway API key or a Vercel OIDC token as Bearer auth. The
host chooses which credential source to use, owns model routing/fallback policy, and treats custom
Gateway endpoint URLs as credential-bearing trusted proxies.

OpenCode Go accepts a redacted API key, not `OAuthAccessToken`. Hosts select the model's protocol
and output limit. Messages uses `x-api-key`; Chat Completions and Responses use Bearer auth. No
Claude/Codex subscription fingerprints are added. Only configure a trusted credential-bearing
`baseUrl` override. See [Go setup](../integrations/provider-setup#opencode-go).

Grok subscription tokens default to the fixed xAI CLI proxy, not the developer API-key origin.
Browser PKCE uses xAI's fixed loopback callback. The package exports device-flow constants only; a
host that cannot listen on the callback must implement device-code initiation, polling, cancellation,
and exchange itself. Validate token provider/freshness before construction, serialize refreshes, and
atomically persist any replacement refresh token. Only configure a custom Grok response URL when it
is a trusted credential-bearing proxy. The default CLI proxy is a private, unsupported surface that
may change; use it only when permitted by xAI's terms.

Claude/Codex/Grok subscription-usage adapters accept the same `OAuthAccessToken` values but do not
refresh or persist them. Go's `fetchOpenCodeGoSubscriptionUsage` accepts a redacted API key instead. Grok usage also requires the authenticated xAI `user_id` and a truthful host integration
version as explicit options; it does not reinterpret generic token `accountId` or impersonate an
official client version. Their private provider endpoints are best-effort. Hosts own polling,
labels, stale-data rules, alerts, and UI; the adapters only fetch and normalize allowance windows
with sanitized errors.

## What the provider gives the loop

Provider layers implement `LLMProvider`. The loop calls that service with messages, tool definitions, system prompt, model id, and optional capabilities. The provider emits text deltas, tool calls, usage, and done/error events.

## OpenAI JSON admission

OpenAI Chat Completions and Responses lowering admits `ToolDef.parameters` and tool-call `params` as
`Schema.Json` before transport. Non-JSON values fail as non-retryable `LLMError` `provider_error`.
`ToolDef.parameters` now admits `ToolJsonSchema` at construction; call params/results remain opaque.
Public Codex `OpenAiCodexTool.parameters` remains
`unknown`. Inbound HTTP JSON and Responses SSE event JSON admit `Schema.Json` before helpers;
non-object SSE JSON is ignored, malformed non-JSON event text fails `invalid_response`, and HTTP
error bodies stay raw text for classification.

Compatible chat endpoints can opt into `OpenAiProviderConfig.reasoningEffortFormat`:
`reasoning-object` sends `{ reasoning: { effort } }`, and `reasoning-effort` sends `reasoning_effort`.
`reasoningContent: true` validates/emits `reasoning_content` (or the normalized `reasoning` thinking field, preferring `reasoning_content` when both are present) and preserves it in assistant replay;
by default this vendor extension is ignored. OpenCode Go enables the latter two options.

Chat stays one JSON body by default; `streaming: true` requests SSE deltas (OpenCode Go chat always
sets it). Only stream against endpoints that serve chat SSE. See the [API reference](../api-reference/agent#providers)
and [Go setup](../integrations/provider-setup#opencode-go).

`OpenAiProviderConfig.extraBody` takes JSON-object input. Lowering discards canonical request fields
without reading their values and snapshots surviving enumerable own data. Accessors are rejected
unread, not evaluated; nonfinite values, cycles and exotic objects fail with a fixed
`Invalid … extraBody JSON: expected a JSON object` and no HTTP request. Root symbols/hidden fields
are omitted; nested hidden/symbol keys and extra array properties fail. DAG aliases are supported;
mutating the input after lowering does not mutate the snapshot. Proxy traps are not guaranteed
side-effect-free. Final composed-body `Schema.Json` admission after lone-surrogate rewriting remains.
Gateway routing projects its declared JSON fields. See [the migration guide](../migration).

## Errors and retries

Provider adapters classify safe metadata into `ProviderErrorInfo`. Raw provider response bodies stay out of protocol/UI. The loop owns bounded retry behavior and usage aggregation.

Subscription-usage requests use separate `ProviderSubscriptionUsageError` variants because they run
outside the LLM loop. They suppress credential-bearing HTTP traces and never preserve raw response
bodies in typed failures.
