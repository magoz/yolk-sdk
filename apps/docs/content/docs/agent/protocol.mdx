Use `@yolk-sdk/agent/protocol` any time your app needs to build messages, inspect stream events, or persist a transcript.

## Create messages

Concrete transcript message variants:

- `UserMessage`
- `AssistantAgentMessage`
- `ToolResultMessage`

`AgentMessage` is the union of those variants, not a fourth message kind:

```ts
type AgentMessage = UserMessage | AssistantAgentMessage | ToolResultMessage
```

`AssistantAgentMessage` is the assistant/model-authored variant. It can contain text, reasoning, host tool calls, provider tool calls, and provider tool results.

Create a normal user message:

```ts
import { UserMessage } from '@yolk-sdk/agent/protocol'

const message = UserMessage.make({ content: 'Summarize this file.' })
```

Add optional model-visible envelope facts:

```ts
const message = UserMessage.make({
  content: 'Summarize this.',
  createdAtMs: Date.now(),
  author: { displayName: 'Magoz' },
  annotations: { timezone: 'Europe/Madrid' }
})
```

Do not put secrets, auth state, private ids, or hidden policy in envelope fields. Providers may send them to models.

## Send files and media

`Content` is either plain text or ordered content parts:

- `TextPart`
- `ImagePart`
- `DocumentPart`
- `AudioPart`

Media sources can be inline base64, durable URLs, or host-owned refs:

```ts
import { ImagePart, UserMessage, urlAttachmentSource } from '@yolk-sdk/agent/protocol'

const message = UserMessage.make({
  content: [
    ImagePart.make({
      source: urlAttachmentSource('https://cdn.example.com/image.webp'),
      mimeType: 'image/webp'
    })
  ]
})
```

Hosts own upload, auth, URL durability, retention, and ref hydration policy. Use
`resolveMessageAttachmentSources` or `resolveMessagesAttachmentSources` to resolve sources throughout
user, assistant, and tool-result content without changing durable history. These Effect-native helpers
also traverse nested assistant provider tool results and preserve envelope/part metadata and ordering.
They do not interpret opaque tool/provider payloads or add provider media capabilities.

For private files, resolve fresh URLs inside each provider attempt, after context projection and
compaction. See [Resolve private attachments](../guides/private-attachments) for authorization,
overflow-retry composition, native tool-result content, and bounded connector downloads.

## Consume events

Streams emit `AgentEvent` values such as:

- `AgentStart`, `AgentEnd`, `AgentError`, `AgentRetry`
- `TurnStart`, `TurnEnd`
- `LLMStreamStart`, `LLMTextDelta`, `LLMReasoningDelta`, `LLMStreamEnd`
- `ToolExecutionStarted`, `ToolExecutionCompleted`, `ToolExecutionError`
- `ToolExecutionAccepted` (a host admitted a background tool call; not completion, no usage)
- `UserMessageEvent`, `AssistantMessageEvent`
- `AgentAwaitingInput`, `QuestionRequested`, approval events

Use `UserMessageEvent` when a host promotes queued user input into a durable stream. The host owns
queue/promotion policy and assigns a stable `eventId` so replay does not project the message twice:

```ts
import { UserMessage, UserMessageEvent } from '@yolk-sdk/agent/protocol'

const event = UserMessageEvent.make({
  eventId: 'session_1:user-message_42',
  message: UserMessage.make({ content: 'Please compare the alternatives too.' })
})
```

Use `isTerminalAgentEvent` to detect logical stream termination.

```ts
import { isTerminalAgentEvent } from '@yolk-sdk/agent/protocol'

for (const event of events) {
  if (event._tag === 'LLMTextDelta') {
    process.stdout.write(event.text)
  }

  if (isTerminalAgentEvent(event)) {
    break
  }
}
```

## Validate transcripts before provider calls

Every assistant host tool call must have a matching `ToolResultMessage` before the next provider request. Use `validateNoDanglingHostToolCalls` before lowering transcripts to providers.

### Preserving tool acknowledgements

Use `toolResultMessageFromResult(result, envelope?)` to copy `toolCallId`, `content`, `isError`,
`structuredContent`, and background `acceptance` into a `ToolResultMessage`. It invents no timestamp,
author, or annotations; pass those optional message-envelope fields explicitly.

An accepted call is settled, not completed. Client and React projections preserve its original call
and receipt across active-event replays (even without event IDs), turn cleanup, and transcript
hydration. Persisted acceptance takes precedence over stale active client runs.
