---
title: Connectors package
description: Define external API actions and turn them into agent tools.
---

Use `@yolk-sdk/connectors` when you want reusable, typed actions for external services such as Afloat, Dropbox, Fortnox, generic IMAP/POP3/SMTP email, Google Gmail/Calendar/Drive, Microsoft Outlook/OneDrive, Notion, Telegram, Todoist, R2, Figma, or custom APIs.

Install:

```bash
pnpm add @yolk-sdk/connectors@canary @yolk-sdk/agent@canary effect@4.0.0-beta.80
```

## Invoke a connector action

```ts
import { Effect } from 'effect'
import { makeCredentialBinding, makeIntegration } from '@yolk-sdk/connectors'
import { TelegramBotTokenSlot, TelegramConnector } from '@yolk-sdk/connectors/telegram'

const integration = makeIntegration({
  connectorId: 'telegram',
  config: { chatId: '123456' },
  credentialBindings: [
    makeCredentialBinding({
      slotId: TelegramBotTokenSlot.id,
      credentialRef: 'telegram-bot-token'
    })
  ]
})

const program = TelegramConnector.invoke({
  integration,
  action: 'telegram.send_message',
  input: { message: 'Hello from Yolk' }
})

const result = await Effect.runPromise(program.pipe(Effect.provide(HostConnectorLayer)))
```

`HostConnectorLayer` provides `CredentialResolver`, `ConnectorHttpClient`, and any provider-specific ports.

## Turn connector actions into agent tools

Wiring fragment; provide host HTTP and credential layers for a separate Google integration:

```ts
import { makeCredentialBinding, makeIntegration } from '@yolk-sdk/connectors'
import { makeConnectorToolModule } from '@yolk-sdk/connectors/agent'
import { GoogleConnector, GoogleOAuthCredentialSlot } from '@yolk-sdk/connectors/google'

const googleIntegration = makeIntegration({
  connectorId: 'google',
  credentialBindings: [
    makeCredentialBinding({
      slotId: GoogleOAuthCredentialSlot.id,
      credentialRef: 'host-google-oauth-credential'
    })
  ]
})

const destructiveGoogleActions = new Set([
  'calendar.delete_event',
  'drive.trash_file',
  'drive.delete_file',
  'gmail.trash',
  'gmail.draft_delete'
])

const writingGoogleActions = new Set([
  'calendar.create_event',
  'calendar.update_event',
  'drive.create_folder',
  'gmail.modify_labels',
  'gmail.untrash',
  'gmail.draft_compose',
  'gmail.draft_update',
  'gmail.draft_reply'
])

const googleTools = makeConnectorToolModule(GoogleConnector, {
  integration: googleIntegration,
  layer: HostConnectorLayer,
  access: action =>
    destructiveGoogleActions.has(action)
      ? 'destructive'
      : writingGoogleActions.has(action)
        ? 'write'
        : 'read'
})
```

Resolve the module with `@yolk-sdk/agent/tools`, pass the tool definitions into the loop, and execute through the returned tool executor.

## Provider modules

| Subpath                                | Use for                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------ |
| `@yolk-sdk/connectors/afloat`          | Afloat remote MCP auth data                                                          |
| `@yolk-sdk/connectors/dropbox`         | Dropbox metadata, search, file management, and host-only file download               |
| `@yolk-sdk/connectors/email`           | Generic IMAP reads/drafts/message state, POP3 reads, and SMTP submission             |
| `@yolk-sdk/connectors/figma`           | Figma remote MCP auth data                                                           |
| `@yolk-sdk/connectors/fortnox`         | Read-only company information, customers, invoices, suppliers, and supplier invoices |
| `@yolk-sdk/connectors/google`          | Gmail, Calendar, and Drive                                                           |
| `@yolk-sdk/connectors/linkedin-search` | Exa people search and Enrich Layer profile/email                                     |
| `@yolk-sdk/connectors/microsoft`       | Microsoft Outlook and OneDrive through Microsoft Graph                               |
| `@yolk-sdk/connectors/notion`          | Notion pages, blocks, databases, data sources, comments, users                       |
| `@yolk-sdk/connectors/r2-storage`      | R2 upload URL with host presigner                                                    |
| `@yolk-sdk/connectors/telegram`        | Telegram bot send/validate                                                           |
| `@yolk-sdk/connectors/todoist`         | Todoist projects, tasks, labels                                                      |

[Fortnox](./fortnox) exposes ten GET-only actions and resource-scoped OAuth hints through one
`fortnox.oauth` binding. Fortnox scopes themselves permit both read and write; the connector's
read-only surface does not narrow the underlying token. Hosts own consent and token lifecycle.

Microsoft Outlook and OneDrive are exposed from the provider-level `microsoft` subpath because
Microsoft Graph is their shared API and OAuth resource boundary. Workload action ids remain
`outlook.*` and `onedrive.*`, while every scoped slot uses the same `microsoft.oauth` binding. One
credential can therefore cover both workloads when consent includes their `Mail.*` and `Files.*`
permissions.

Outlook inputs use `/me` by default; set `mailbox` for Exchange Online shared/delegated access.
Application hosts use `mailboxAccessMode: 'application'`. OneDrive inputs use `/me/drive` by default;
set `driveId` for an explicit drive, `oneDriveAccessMode: 'delegated_all'` for broader delegated
permissions, or `oneDriveAccessMode: 'application'` for application tokens. Discovery and metadata
stay on `onedrive.*` actions. Original file bytes use host-only `downloadOneDriveItem` with
`ConnectorBinaryHttpClient`; create/update use the separate binary-write port. Resumable sessions remain unimplemented. Default Microsoft
tools still need `CredentialResolver` and `ConnectorHttpClient`. The host still owns
Entra tenant policy, OAuth callbacks, refresh, storage, consent,
application resource scoping, Exchange grants, network policy, and file materialization.

Dropbox follows the same split: `dropbox.*` actions cover discovery, metadata, and file management,
while original file bytes use host-only `downloadDropboxFile` with `ConnectorBinaryHttpClient` and
the `files.content.read` scope. Host-only create/update require `files.content.write`.

Google's `gmail.get_thread` action returns normalized messages with decoded message text and
attachment metadata, without raw MIME or attachment content. See the
[Connectors catalog](../integrations/connectors#fetch-a-normalized-gmail-thread) for its required
format and output contract.

Google Drive actions stay in the provider-level `google` subpath and share the existing
`google.oauth` credential binding with Gmail and Calendar. Metadata reads request
`drive.metadata.readonly`; folder creation, trash, and permanent deletion request `drive.file`,
which is limited to files created by or explicitly opened/shared with the app. The host owns OAuth
refresh, consent policy, Google Picker integration, restricted-scope compliance, and binary file
transfer.

Outlook and generic IMAP email support `set_read` (with boolean `isRead`), `trash`, and `untrash`
actions in their respective `outlook.*` and `email.*` namespaces. Outlook calls Graph directly;
generic email requires optional host `EmailClient.setRead`, `trash`, and `untrash` methods.
POP3/SMTP do not support these mailbox-state actions. Restore defaults to the inbox rather than
remembering the original folder. See the [Connectors catalog](../integrations/connectors) for
inputs, permissions, and safe IMAP adapter requirements.

## Transfer files

See [Transfer connector files](./files) for the full capability matrix, raw-byte download/export and
create/update helpers, consent, provider limits, concurrency guarantees and host transport duties.
This also covers R2, Drive, Fortnox, Notion, email, Telegram, Todoist and reuse of Afloat/Figma MCP.
Bytes and write helpers are never added to generic connector action serialization.

## What the host provides

Your app stores, encrypts, refreshes, revokes, and audits credentials. It also owns OAuth routes, callbacks, consent scopes, identity mapping, authorization, and HTTP execution policy.
