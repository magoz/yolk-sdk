Use `@yolk-sdk/mcp` when your app needs to connect an agent to Model Context Protocol servers.

For auth, local stdio, and server policy, see [MCP auth, local servers, and server policy](./auth-local-server).

Install:

```bash
pnpm add @yolk-sdk/mcp@canary @yolk-sdk/agent@canary effect@4.0.5
```

## Connect with the full MCP v2 client

Use the official client API for tools, resources, prompts, completions, MRTR, subscriptions, response caching, and OAuth protocol helpers:

```ts
import { Client, StreamableHTTPClientTransport } from '@yolk-sdk/mcp/client'

const client = new Client(
  { name: 'my-app', version: '1.0.0' },
  { versionNegotiation: { mode: 'auto' } }
)

await client.connect(new StreamableHTTPClientTransport(new URL('https://example.com/mcp')))

const tools = await client.listTools()
const resources = await client.listResources()
const prompts = await client.listPrompts()
```

`mode: 'auto'` prefers stateless MCP `2026-07-28` and falls back to initialize-based servers. Use `{ pin: '2026-07-28' }` for modern-only behavior. The upstream `Client` default remains legacy for compatibility.

Import official wire schemas from `@yolk-sdk/mcp/core`. Import Node stdio transports from `@yolk-sdk/mcp/client/node` and `@yolk-sdk/mcp/server/node`.

## List remote MCP tools for a Yolk agent

```ts
import { Effect } from 'effect'
import { FetchHttpClient } from 'effect/http'
import type { McpRemoteServerConfig } from '@yolk-sdk/mcp/client'
import { listRemoteMcpServerTools } from '@yolk-sdk/mcp/client'

const config = {
  name: 'docs',
  type: 'remote',
  url: 'https://example.com/mcp'
} satisfies McpRemoteServerConfig

const tools = await Effect.runPromise(
  listRemoteMcpServerTools(config).pipe(Effect.provide(FetchHttpClient.layer))
)
```

Each item contains:

- `serverName`
- original `mcpToolName`
- Yolk `ToolDef` as `def`

Pass `tools.map(tool => tool.def)` into the agent loop.

## Call a remote MCP tool

```ts
import { callRemoteMcpServerTool } from '@yolk-sdk/mcp/client'

const result = await Effect.runPromise(
  callRemoteMcpServerTool({
    config,
    mcpToolName: 'search',
    toolCallId: 'call_123',
    params: { query: 'Yolk SDK' }
  }).pipe(Effect.provide(FetchHttpClient.layer))
)
```

The result is a Yolk `ToolResult`, ready to feed back into the agent loop.

## Confirm tool calls with form elicitation

Some servers confirm destructive tools with MCP form elicitation over multi round-trip requests
(MRTR, protocol `2026-07-28`): the first `tools/call` answers an `InputRequiredResult` (a form plus
an opaque `requestState`), and the client retries the same call with the user's decision. Yolk
models this for durable hosts: nothing blocks waiting for a person.

Opt in with `elicitation: { form: true }`. The listing and the resumable call functions then declare
`elicitation.form` in the per-request `_meta` client capabilities of a modern connection (never in a
legacy `initialize`). `callRemoteMcpServerToolResumable` answers a typed outcome:

An integration fragment: `collectDecision` stands for the host's own flow (persist the pause, show
the form to a person, await their answer, possibly in another process). Never auto-accept a
confirmation; when no person decides, answer `decline` or `cancel`.

```ts
import {
  callRemoteMcpServerToolResumable,
  resumeRemoteMcpServerToolCall,
  type McpClientOptions,
  type McpElicitationResponse,
  type McpFormElicitation
} from '@yolk-sdk/mcp/client'

// Host-owned: renders the form, waits for a person, and returns their decision.
declare const collectDecision: (form: McpFormElicitation) => Promise<McpElicitationResponse>

const options: McpClientOptions = { elicitation: { form: true } }
const call = { config, mcpToolName: 'delete-invoice', toolCallId: 'call_123', params, options }

const outcome = await Effect.runPromise(
  callRemoteMcpServerToolResumable(call).pipe(Effect.provide(FetchHttpClient.layer))
)

if (outcome._tag === 'InputRequired') {
  // Persist `outcome.inputRequired` first: the decision may take hours and another process.
  const pending = outcome.inputRequired
  const entries: Array<[string, McpElicitationResponse]> = []

  for (const form of pending.elicitations) {
    // One decision per form, keyed by `form.key`, from a person.
    entries.push([form.key, await collectDecision(form)])
  }

  // `Object.fromEntries` keeps any server key as an own property (even `__proto__`).
  const responses = Object.fromEntries(entries)

  const resumed = await Effect.runPromise(
    resumeRemoteMcpServerToolCall({ ...call, inputRequired: pending, responses }).pipe(
      Effect.provide(FetchHttpClient.layer)
    )
  )
}
```

`McpInputRequired` is a Schema class: encode it with `Schema.encodeUnknownEffect` to persist it and
decode it in another process. Each `McpFormElicitation` carries the server's `key`, `message`, and
`requestedSchema` (flat primitive properties, kept as received). The pause is bound to its call
(`mcpToolName`, `argumentsDigest`) and carries the listed tool definition. Answer every elicitation
with `accept` (with `content`), `decline`, or `cancel`; decisions are checked against each form
(type (integer vs number), `required`, `const`, `enum`, titled `oneOf`, `minLength`/`maxLength`, `format` (email, uri, date, date-time), `minimum`/`maximum`, `items.enum`, titled `items.anyOf`, `minItems`/`maxItems`) before sending, and the server validates them again. The
resume is re-sent as a new request on a new connection with the same tool call, the exact
`requestState`, and the decisions as `inputResponses`. It lists nothing: the pause's tool definition
(`name`, `inputSchema`, `outputSchema`) drives header mirroring and the structured-output check, and
an invalid one fails `malformed` before sending. With that definition the official client does not
re-list and retry after a `HEADER_MISMATCH` (`-32020`), so a server that changed the tool's
`x-mcp-header` declarations since the pause answers `McpError` (`cause: 'protocol'`). The server
may pause again.

Failures are typed. `McpInputRequiredError` covers a `malformed` or `too_large` pause. The default
bound is 256 KiB of JSON and 16 requests; set `elicitation.maxInputRequiredBytes` to a positive
integer (checked before connecting). It applies separately to the server-provided pause (checked
after the body is buffered, without the tool definition) and to the listed tool definition (checked
before the call, so an oversized definition fails with nothing sent and never strands a pause). It
also covers an `unsupported_request` (URL mode,
sampling, roots, or any input without the opt-in), `invalid_responses` and `mismatched_resume`
(another tool or other arguments; both checked before sending), and `unsupported_era` (resuming on a
legacy connection). The pause is decoded from the raw `input_required` response as the server sent it:
the response the official client resolves the call with (matched by its own `Number(id)` coercion;
an id not identical to the call's fails `malformed`), captured at the transport before the client
normalises it. A non-string `requestState` or non-object `inputRequests` fails `malformed` instead of
passing as a valid or load-shedding pause; responses with other ids are ignored. Formats are checked
by syntax: RFC 3339 dates (a leap second only at `23:59:60` UTC), an absolute RFC 3986 URI (IPv6
literals per its grammar; not WHATWG URL parsing), and a pragmatic
mailbox (a dot-atom local part, `@`, a hostname of at least two labels). MCP `-32021` becomes
`McpClientCapabilityRequiredError` with `requiredCapabilities`. A server that reports a missing
capability as a tool error (for example Afloat's `CLIENT_CAPABILITY_REQUIRED`) answers a `Complete`
outcome with `isError: true`.

Legacy (pre-`2026-07-28`) elicitation is a server-initiated request that must be answered while the
call is open, so it is not supported: an opted-in host never declares elicitation on a legacy
connection. `callRemoteMcpServerTool` keeps its behavior and never declares it.

Use `@yolk-sdk/mcp/client/node` only in Node hosts:

## Build a full MCP v2 server

Use `McpServer` and `createMcpHandler` for tools, resources, prompts, completions, MRTR, and subscriptions:

```ts
import { McpServer, createMcpHandler } from '@yolk-sdk/mcp/server'

const handler = createMcpHandler(() => {
  const server = new McpServer({ name: 'my-server', version: '1.0.0' })
  // Register tools, resources, and prompts here.
  return server
})

export default { fetch: handler.fetch }
```

`createMcpHandler` serves stateless MCP `2026-07-28` and legacy initialize-based HTTP clients. Put deployment authentication plus `Origin` and `Host` validation in front of `handler.fetch`.

## Expose Yolk tools through MCP

Use `makeMcpToolServer` from `@yolk-sdk/mcp/server` to expose a tool-only Yolk adapter. Its HTTP entrypoint accepts both modern and legacy requests. Use the official `McpServer` surface when you need other core capabilities.

`handleHttpRequest` finishes every tool call before its Effect returns, so you can provide its requirements from a scoped request layer: when an answer is an SSE stream (always for 2025-era requests), it is read to its end first and returned with the same status, headers and events. Only `subscriptions/listen` streams are returned as they open. When the client cancels a request (on Streamable HTTP, by closing its response stream), the tool's Effect is interrupted.

## Conformance cases

`@yolk-sdk/mcp/conformance` (experimental) holds nine read-only conformance cases that check the
wire claims the remote client relies on, against any MCP server you point them at, plus the opt-in
`mcpElicitationDeclarationCase` for hosts that declare form elicitation. See
[MCP conformance](../api-reference/conformance#mcp-conformance).

## Security defaults

Remote MCP requires HTTPS by default. Localhost HTTP is an explicit dev policy. Local stdio receives explicit env only and does not inherit host process env by default.
