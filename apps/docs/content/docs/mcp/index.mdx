Use `@yolk-sdk/mcp` when your app needs to connect an agent to Model Context Protocol servers.

For auth, local stdio, and server policy, see [MCP auth, local servers, and server policy](./auth-local-server).

Install:

```bash
pnpm add @yolk-sdk/mcp@canary @yolk-sdk/agent@canary effect
```

## Connect with the full MCP v2 client

Use the official client API for tools, resources, prompts, completions, MRTR, subscriptions, response caching, and OAuth protocol helpers:

```ts
import { Client, StreamableHTTPClientTransport } from '@yolk-sdk/mcp/client'

const client = new Client(
  { name: 'my-app', version: '1.0.0' },
  { versionNegotiation: { mode: 'auto' } }
)

await client.connect(new StreamableHTTPClientTransport(new URL('https://example.com/mcp')))

const tools = await client.listTools()
const resources = await client.listResources()
const prompts = await client.listPrompts()
```

`mode: 'auto'` prefers stateless MCP `2026-07-28` and falls back to initialize-based servers. Use `{ pin: '2026-07-28' }` for modern-only behavior. The upstream `Client` default remains legacy for compatibility.

Import official wire schemas from `@yolk-sdk/mcp/core`. Import Node stdio transports from `@yolk-sdk/mcp/client/node` and `@yolk-sdk/mcp/server/node`.

## List remote MCP tools for a Yolk agent

```ts
import { Effect } from 'effect'
import { FetchHttpClient } from 'effect/unstable/http'
import type { McpRemoteServerConfig } from '@yolk-sdk/mcp/client'
import { listRemoteMcpServerTools } from '@yolk-sdk/mcp/client'

const config = {
  name: 'docs',
  type: 'remote',
  url: 'https://example.com/mcp'
} satisfies McpRemoteServerConfig

const tools = await Effect.runPromise(
  listRemoteMcpServerTools(config).pipe(Effect.provide(FetchHttpClient.layer))
)
```

Each item contains:

- `serverName`
- original `mcpToolName`
- Yolk `ToolDef` as `def`

Pass `tools.map(tool => tool.def)` into the agent loop.

## Call a remote MCP tool

```ts
import { callRemoteMcpServerTool } from '@yolk-sdk/mcp/client'

const result = await Effect.runPromise(
  callRemoteMcpServerTool({
    config,
    mcpToolName: 'search',
    toolCallId: 'call_123',
    params: { query: 'Yolk SDK' }
  }).pipe(Effect.provide(FetchHttpClient.layer))
)
```

The result is a Yolk `ToolResult`, ready to feed back into the agent loop.

## Use local stdio MCP

Use `@yolk-sdk/mcp/client/node` only in Node hosts:

See [MCP auth, local servers, and server policy](./auth-local-server#local-stdio) for a runnable Node
example, explicit environment rules, and the required `allowLocalServers` opt-in.

Worker/browser code should stay on `@yolk-sdk/mcp/client`.

## Build a full MCP v2 server

Use `McpServer` and `createMcpHandler` for tools, resources, prompts, completions, MRTR, and subscriptions:

```ts
import { McpServer, createMcpHandler } from '@yolk-sdk/mcp/server'

const handler = createMcpHandler(() => {
  const server = new McpServer({ name: 'my-server', version: '1.0.0' })
  // Register tools, resources, and prompts here.
  return server
})

export default { fetch: handler.fetch }
```

`createMcpHandler` serves stateless MCP `2026-07-28` and legacy initialize-based HTTP clients. Put deployment authentication plus `Origin` and `Host` validation in front of `handler.fetch`.

## Expose Yolk tools through MCP

Use `makeMcpToolServer` from `@yolk-sdk/mcp/server` to expose a tool-only Yolk adapter. Its HTTP entrypoint accepts both modern and legacy requests. Use the official `McpServer` surface when you need other core capabilities.

## Security defaults

Remote MCP requires HTTPS by default. Localhost HTTP is an explicit dev policy. Local stdio receives explicit env only and does not inherit host process env by default.
