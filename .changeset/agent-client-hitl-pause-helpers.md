The client names the pause a durable HITL answer is for (#338), so hosts no longer build `?pause=` into the endpoint by hand. `StreamAgentRunHitlResponseEventsRequest` takes an optional `pause` (the `eventId` of the `AgentAwaitingInput` that asked): the HITL resume helpers send it as the `pause` query parameter of the POST only, and the continuation reads that follow use `endpoint` as given (a blank `pause` fails before the POST). `@yolk-sdk/agent/client` adds `HitlPauses` (an Effect Schema: request id -> pause id, `emptyHitlPauses`) with the pure `rememberHitlPause(pauses, event)`, which records the pause of each request an `AgentAwaitingInput` holds (the latest wins; a pause without an `eventId` forgets the earlier one), and `hitlPauseFor(pauses, response)`. `useAgentChat` keeps that map in its state (`AgentChatState.hitlPauses`, from every applied event, `applyEvent` replays included, reset with `seenEventIds` when a new stream starts) and puts the answer's pause on its transport request (`AgentChatTransportRequest.pause`, absent when no pause with an `eventId` asked); the default transport ignores it. Hosts that already put `?pause=` in the endpoint keep working; pass `pause: request.pause` instead.
