Add six `read` conformance cases that send exactly the requests of the read-only leftover lookups, each with a synthetic `unverified` fixture shaped from the provider's API reference: `todoist.projects.list-cursor-paging` (the `limit=200` project listing, then one project per page through `next_cursor`), `github.issues.open-listing` (the open-issue listing and the work issue's first comment page, `per_page=100`, `page=1`), and `google.gmail.label-listing`, `google.gmail.draft-search`, `google.calendar.free-text-query` (it claims only that each answered event mentions `yolk` or `conformance` somewhere Google searches, organizer and creator included, observed at the port), and `google.drive.list-includes-trashed` (with a new `driveTrashedFileId` seed, a file in Trash inside `driveFolderId`, which the listing must answer). The Google draft and event lifecycle cases also check, live only, that the lookup's search finds their own item before they delete it: the new `GoogleConformanceLookupRecall` reference (default off) turns that on, and the repository's live runner sets it.

The Todoist, GitHub, and Google emulators now serve those requests, citing the new cases, so `findTodoistConformanceLeftovers`, `findGithubConformanceLeftovers`, and `findGoogleConformanceLeftovers` run against them and report what the state holds. This supersedes the earlier changesets `emulators-todoist-telegram`, `emulators-github`, and `emulators-google`, which say these lookups fail closed against the emulators. The routes: `GET /api/v1/projects` with cursor paging on `/todoist` (its task and project cursor counters now never reset, so no cursor value crosses a `reset` or `seed`); `GET /repos/{owner}/{repo}/issues` (`state=open`, `page=1`) and a `page=1` comment listing on `/github`, whose seed gains `impliedIssues` (`closed` only on the default seed as the listing fixture records it; a seed that replaces `issues` or sets `nextIssueNumber` gets `unknown`, which refuses the listing while implied numbers exist, unless it names `closed` itself); and `GET .../labels`, `GET .../drafts`, the `q` event query, and the Drive listing with trashed items on `/google`, whose seed gains `listedLabels` (the system and paging labels as the listing fixture records them) and whose default practice folder now holds the seeded trashed file. The Google draft search and event query are recorded only empty and stay fixture-only: the draft search answers only while the state holds no draft and no message labelled `DRAFT`, and the event query only while no event of the calendar, cancelled ones included, holds `yolk` or `conformance` in its summary or description, nor, while the calendar holds events, its id or summary (the organizer) or the practice address (the creator), since Gmail's search syntax and Calendar's free-text matching cannot be emulated honestly; otherwise they fail closed (for example after the event cases, whose cancelled run events stay in the state). New test-only drill knobs: `projectCursorRestarts` (Todoist), `issueListingLinksNext` (GitHub), and `labelListingOmitsUserLabels`, `draftSearchDraftsNull`, `eventQueryIgnored`, `trashedListingOmitsTrashed` (Google); `listIncludesTrashed` now adds only trashed folders created here to a listing without trashed items.
