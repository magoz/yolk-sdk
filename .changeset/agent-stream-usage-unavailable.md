Signal when a streamed model call completes without the usage report it asked for (#109). `LLMDone` and the protocol `LLMStreamEnd` gain an optional `usageUnavailable: true`. The streamed chat provider (generic OpenAI-compatible chat, Vercel AI Gateway with `streaming: true`, OpenCode Go `chat-completions`) sets it when a stream ends after its finish chunk without the usage chunk `stream_options.include_usage` requested; the Codex provider sets it when its EOF-completion compatibility completes a stream without `response.completed`; the Claude provider sets it when its EOF-completion compatibility completes a stream without `message_delta` (any `message_start` usage it sent is then partial). The loop forwards it from the provider's `Done` onto that model stream's `LLMStreamEnd`. These turns still complete normally, as before, since failing them would re-run and re-bill the model; hosts can now tell "usage was requested but never arrived" from "no usage" and decide how to account for it. The field is absent otherwise (JSON responses, complete streams, other providers) and on events recorded before it existed, so persisted event streams decode unchanged, and no event or `LLMEvent` tag is added.
