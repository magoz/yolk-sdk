Add the experimental, Node-only `@yolk-sdk/emulators/mcp` subpath: `makeMcpEmulator`, a stateful emulator on the pinned `@emulators/core` custom runtime (loaded lazily) that follows the fixture-only rule for the two synthetic MCP servers of `@yolk-sdk/mcp/conformance`: profile `synthetic-modern` on `https://mcp.example.test/modern/mcp` (stateless `2026-07-28`, JSON answers) and profile `synthetic-legacy` on `https://mcp.example.test/legacy/mcp` (an `initialize` handshake with sessions, SSE answers). The sixteen synthetic fixtures are copied as data (`mcpEmulatorFixtures`; the emulator never imports `@yolk-sdk/*`). A JSON-RPC request is answered only when it equals a recorded request (only recorded methods per profile; `mcp-method` and `mcp-protocol-version` as recorded; params as recorded except JSON key order and the `_meta` client info's name and version), with the recorded bytes and the request id (an integer from 0 to 2^53 - 1, or 1 to 64 printable ASCII characters) substituted at exactly the recorded place. `initialize` mints `yolk-emu-session-<n>` from a counter that never resets (at most 256 sessions; `reset` and `seed` clear them), the standing `GET` answers the recorded 405 on a ready session, and the seed's `modernListing` selects the recorded one-page or two-page modern listing (its cursor issued per generation). The bearer is never stored, ledgered, or echoed: routes see only its digest, compared only with the public reserved invalid credential `yolk-conformance-invalid-credential-0000`, whose recorded 401 is answered byte for byte. Everything else (`DELETE`, `ping`, resources, prompts, batches, a JSON body repeating a key, `mcp-*` headers no recording carries, cursors not issued, other tools or arguments, a bearer repeated in any header, and a bearer an answer or minted session id or cursor would repeat) answers a 400 not-emulated, ledgered with constant text only, that writes nothing and uses up no fault. The manifest (`mcpEmulatorRoutes`) has one `RPC <origin><path>#<method>` row per recorded JSON-RPC method plus the `GET` row, all unverified reads, so no pending evidence entry. The shared internal wrapper gains backward-compatible opt-ins for it: route variants (one HTTP route answering several manifest rows); streamed commits whose answer the plan prepares, with `truncate-after-chunks` faults (`makeChunkedStatefulEmulator`) that send the prepared answer cut short and never run the commit, so a truncated request writes nothing (one that cannot apply answers 500 and is not used up); `constantRefusals`, `guardAllHeaders` (every request header name and value checked for a credential repeat), and `guardOutput` (a prepared answer or persisted value repeating the bearer is refused before any fault or write), all fail-closed mode only; `uniqueJsonKeys` (a JSON body repeating a key is refused); and `EmulatedRequest.headerNames`. One change reaches every stateful-wrapper emulator: the fault match schema shared by `DropboxFaultMatch`, `NotionFaultMatch`, `GithubFaultMatch`, `GoogleFaultMatch`, and `LinkedInSearchFaultMatch` gains an optional `route` (a manifest route template; a value naming no manifest row is rejected when the fault is added), and `match.method` is documented as the HTTP method. Emulators that take none of the opt-ins otherwise behave as before. Includes status and truncation faults, an `/_emulate/*` control plane, and test-only drill knobs (one per MCP case).
