Add durable MCP form elicitation (multi round-trip requests, protocol `2026-07-28`) to the remote client. `McpClientOptions.elicitation: { form: true }` is the host opt-in: only then do `listRemoteMcpServerTools` and the new resumable call functions declare `elicitation.form` in the per-request `_meta` client capabilities of a modern connection (never in a legacy `initialize`). `callRemoteMcpServerToolResumable` answers a Schema-backed `McpToolCallOutcome`: `Complete` (the adapted `ToolResult`) or `InputRequired` (`McpInputRequired`: bounded, decoded form elicitations with `key`, `message` and `requestedSchema`, the opaque `requestState`, the call binding `mcpToolName` and `argumentsDigest`, and the listed tool definition), which the host persists and decides on later. `resumeRemoteMcpServerToolCall` checks the call against the binding and re-sends it as a new request on a new connection, without listing, with the exact `requestState` and the decisions (`accept` with content, `decline`, `cancel`) as `inputResponses`, checked against the forms (type, `required`, `const`, `enum`, titled `oneOf`, `items.enum`, titled `items.anyOf`) before sending. Failures are typed: `McpInputRequiredError` (`malformed`, also for a non-positive-integer `maxInputRequiredBytes` (checked before connecting) or a carried tool definition that is not a valid tool; `too_large` past the bound (256 KiB by default, up from the 64 KiB of the first draft) applied separately to the server-provided pause and to the listed tool definition (checked before the call, so nothing is sent), or past 16 requests; `unsupported_request` for URL mode, sampling, roots or input without the opt-in; `invalid_responses`; `mismatched_resume`; `unsupported_era`) and `McpClientCapabilityRequiredError` for MCP `-32021`. The official client wrongly validates an `input_required` answer as output, so every resumable call passes the listed or paused tool definition without its `outputSchema` (never the SDK response cache), compiles the output schema before calling, and validates complete results itself, also on resume. Legacy-era server-initiated elicitation is not supported. `callRemoteMcpServerTool` is unchanged and never declares the capability. `@yolk-sdk/mcp/conformance` adds the opt-in `mcpElicitationDeclarationCase` with `mcpConformanceElicitationFixtures`, outside the default suite. With the carried definition set, the official client makes no `HEADER_MISMATCH` re-list-and-retry on resume.
