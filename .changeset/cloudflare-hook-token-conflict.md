Breaking (0.x minor): the Cloudflare runtime now refuses a hook whose token another live hook holds, as Vercel and `TestWorkflowWorld` do (#331). Before, a newer run's `createHook` overwrote the `hook:<token>` index and took the token from a run whose hook was still live, so later `resumeHook` calls reached the newer run, and disposing a hook did nothing. Now one live hook holds a token at a time: as the platform creates a hook at its run's next suspension, after the run's disposals since, the runtime decides once the body is idle (the next macrotask), applying the run's disposals first. A hook whose token another live hook (of any run, its own included) still holds is refused: creating it succeeds, awaiting it rejects with the new `HookConflictError` (`token`, `conflictingRunId`, exported from `./cloudflare`), the refusal is journaled so a replay sees it too, and the holder keeps the token and its answers. Disposing a hook (`using`, or the new `hook.dispose()`) frees its token only while it holds it, and a run's end frees its hooks' tokens; an answered hook keeps its token until then, and a further `resumeHook` to it succeeds with the payload dropped (before: `HookNotFoundError`). Hosts whose runs shared a token between live hooks now see the later hook refused: give each pause its own token, or dispose the previous hook before the run waits again. `ExecutionHost.registerHook` is replaced by `claimHook` (returning the new `HookClaim` type), and `WorkflowRunStub.hookRegister` by `hookClaim` and `hookHeld`: the index names the run that took the token last and asks it whether it still holds the token before another run takes it. The index decides one claim at a time, a hook takes payloads only once the index granted its claim (until then `resumeHook` answers `HookNotFoundError`; retry while the pause is pending), a failed call to the index is retried with backoff under the step guard alarm, and a replay disposes its hooks again and asks the index again for a hook that still has its token entry, which repairs entries the previous build left. Drain or cancel runs waiting on tokens several runs share before upgrading (see the migration guide). README "Cloudflare runtime" lists what still differs from Vercel.
