Add `markChatRunStart` (`@yolk-sdk/agent/react`) and `markAgentRunStart` (`@yolk-sdk/agent/client`) for hosts that rebuild chat or client state from a snapshot (#355). Each sets the run start `AgentStart` sets (`turnStart`: turn `0`, `run: true`; chat: after the last message, either chat state; client: `firstRun` = `toolRuns.length`). A host that reads a resumed run from a cursor past its `AgentStart` (o-o's `fromSnapshot` after a HITL answer) had no turn start, so the resumed tool batch acted on the last card or run holding its call id, which could be an earlier turn's call reusing it. With the run start, the batch reaches the snapshot's cards and runs only as the same call or, for answers, the one holding their request, and adds its own otherwise. A snapshot taken mid-turn keeps working for that turn's host events; its later model events before the next `LLMStreamStart` still count as replays, as for a client that connected mid-turn (documented in `client-react.mdx` and the READMEs).
