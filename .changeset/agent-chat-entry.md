'@yolk-sdk/agent': minor

New `@yolk-sdk/agent/chat` subpath: the chat projection without React (messages, items, the event fold, the chat reducer, actions, session events), for hosts on another UI framework or folding on a server. `@yolk-sdk/agent/react` re-exports it whole and adds `useAgentChat`, so its imports keep working.

- A streamed event (deltas, tool input, the answer, tool-batch updates) no longer costs the whole chat: the projection reads and replaces only the event's turn, and every message an event did not change keeps its reference (a list keyed by message id redraws only what changed). Turn boundaries (`LLMStreamStart`, `AgentStart`, terminal events, errors) and events that add a message still scan the chat once. `pnpm bench:chat` measures it: about 15 µs per event after an 8,000-row history, where it was about 600 µs. A projection that folds a whole session also keeps one executions entry per model step: tagged events now find theirs from the latest run back and skip ended or retired runs (after 800 earlier runs, 12,800 entries: about 21 µs per delta, where it was about 780 µs), and a new execution's start still reads every entry once.
- Breaking: `seenEventIds` on `AgentChatEventProjectionState` and `AgentChatState` is now an Effect `HashSet<string>`, not an array (a replay check and an insert cost the same however long the stream ran). Build states with `makeAgentChatEventProjectionState` or `initialAgentChatState`; read it with `HashSet.has` or `[...state.seenEventIds]`; a host that cleared it to `[]` uses `HashSet.empty()`. The client's `AgentClientState.seenEventIds` is unchanged.
- Migrating a stored state: one saved with `JSON.stringify` (an array of ids) loads by replacing the array with `HashSet.fromIterable(stored.seenEventIds)`, or, for a state saved with `Schema.encodeEffect(Schema.toCodecJson(AgentChatEventProjectionStateSchema))` (or `AgentChatStateSchema`), by decoding with the same codec. Store new states with that codec: `JSON.stringify` and `structuredClone` of a state no longer round-trip it (`seenEventIds` comes back as a plain object that `HashSet` functions throw on).
- Tool events and the committed-answer reconciliation find a turn's anchor message searching back from the chat's end, so when message ids repeat (a terminal event appends run messages the chat lacked numbered from 0, a second `message-0-user`), the latest message with the id is the anchor, where it was the first.
- `stepAgentChatProjectionAll(state, events, options)` folds a batch of events as `stepAgentChatProjection` does one: it returns the `projection`, the `statusEvents` to fold into the run's status (each event's `missedStart`, then its `statusEvent`) and `messageIdsChanged` (whether the chat's message ids, in order, changed).
- The projection's state has Effect Schemas, and its types are derived from them: every `…Schema` export of `@yolk-sdk/agent/chat` (`AgentChatEventProjectionStateSchema`, `AgentChatStateSchema` and the Schemas they are made of, `src/chat/chat-schemas.ts`), the generic `AgentExecutionsSchema(output)` on `@yolk-sdk/agent/client` (also re-exported from `/chat` with `HitlPauses`), and `MessageEnvelopeSchema` (a message's `createdAtMs`, `author` and `annotations`) on `@yolk-sdk/agent/protocol`. Constructors keep the plain name and Schemas get `Schema` (`ChatToolState` / `ChatToolStateSchema`); `AgentChatSessionEvent` and `HitlPauses` keep their earlier names. `Schema.toCodecJson(schema)` is a JSON form (`seenEventIds` as an array of ids, options as `{ _tag, value }`); a decoded state continues the fold as the original does. `AgentChatPart`, `ChatToolState` and `AgentChatExecutionOutput` stay `Data.taggedEnum` constructors.
