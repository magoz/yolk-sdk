Bind tool approval to the call instead of the tool's current policy when a pause resumes. Previously `prepareApprovalCall` checked whether the tool still required approval before reading the recorded answer, so a tool whose policy flipped to automatic between the request and the answer ran even when the human denied it. In a resume batch, an exact-match recorded `ToolApprovalResponse` now wins (denied: the denied result, never executed; approved: executed), and a denial under another approval id of the same call (after an execution-mode change) also denies. New optional `awaitingRequests` (the resumed pause's `AgentAwaitingInput.requests`) on `run`, `runToolBatch` and `prepareToolBatch` keeps an unanswered approval request pending even when the tool no longer requires approval: the same request while it still names the call, else a fresh one, its preview recomputed (or dropped without a previewer). Fresh model-turn batches keep the policy-first order because providers may reuse call ids; `prepareToolBatch` and `runToolBatch` take an explicit `resume` (default: `awaitingRequests` or responses given). Hosts must therefore pass only the responses of the batch being resumed (non-empty `hitlResponses` means resume), or set `resume` explicitly. `runRuntime` passes its logged pause automatically with only the current pause chain's responses (those since the last completed, failed or interrupted run), and a transcript resume no longer treats a provider-reused call id as settled by an earlier call's result, and `@yolk-sdk/vercel-workflows` passes each resumed tool step the pause's requests (`VercelAgentWorkflowToolBatchStepInput.awaitingRequests`) for hosts to forward.
