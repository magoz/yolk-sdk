Breaking (0.x minor): `TestWorkflowWorld` now refuses a hook whose token another live hook holds, as the platform does (#318). Before, it registered both: two live runs sharing a token sent every `resumeHook` to the older run, and within one run the newer hook replaced the older one. Now creating the hook still succeeds, but awaiting it rejects with `TestWorkflowHookConflictError` (named `HookConflictError`, with `token` and `conflictingRunId`, and the platform's message without its docs link), and the hook holding the token keeps it and its answers. As the platform creates a hook at its run's next suspension, after the run's disposals since, the world decides once the code that created the hook yields: disposing the previous hook right after creating the next one, before awaiting, frees the token for it. A token freed by disposing its hook or by its run ending can be taken again. Disposing a hook also no longer deletes a later hook that took its token since (a second dispose of an earlier hook used to). `TestWorkflowHookConflictError` is no longer deprecated; its constructor takes an optional `conflictingRunId`. Host tests in which two live hooks share a token now see the later one refused: give each pause its own token.
