`@yolk-sdk/mcp/conformance` adds the opt-in `mcpServerPingCase` (`mcp.legacy.server-ping`, read, legacy era only; not in `mcpConformanceCases`) and its synthetic fixture `mcpConformanceServerPingFixtures` (`evidence: 'unverified'`; its note cites MCP `2025-11-25` basic/utilities/ping, basic/transports and basic/lifecycle), with the builder `legacyServerPingListingExchanges` and the constant `mcpConformanceServerPingRequestId`. Run it for a legacy target that pings its clients: the listing must hold a server `ping` request (else the precondition fails), and the real client must answer each ping exactly once with an empty JSON-RPC result on a POST carrying the issued session, which the server accepts with 202 and no body. `2026-07-28` removed `ping` and server-to-client requests, so it never applies to modern targets. `mcp.transport.response-encoding` no longer reads a client-sent response (such as the answer to a server ping) as a request, so it passes against a pinging server. Methods the client never sends (`DELETE`, its own `ping`, `resources/*`, `prompts/*`, `completion/*`, `logging/setLevel`, `tasks/*`, batches) stay uncovered, with the reasons in the package notes.
