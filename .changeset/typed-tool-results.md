Typed tool results (ADR 0013): a tool's typed output is the single contract for code mode scripts, files are typed fields of that output, and script values never contain file labels.

- `@yolk-sdk/agent`: `makeTool` overloads. With `output`, `execute` returns `{ output }`; Yolk encodes it with `Schema.toCodecJson(output)` (a value that does not encode is a value-free `execution` `ToolError`) and shows the model compact JSON with file labels, or `render(value, files)`. Without `output`, `execute` returns `{ content }`. Returning a raw `ToolResult` still works this canary but is deprecated; with `output`, its `structuredContent` is kept only when it matches the schema's JSON encoding (otherwise dropped and logged). `output` schemas must encode without services (`ToolOutputSchema`). New protocol file fields: `ToolFile` (tools return `FileBytes`, optionally `view: true`; the encoding holds `FileRef` or `FileUnavailable`), `ToolFileCapture` (provided by `resolveTools` to every registration; `makeToolFileCapture`), `typedToolResult`, `encodeToolOutput`, `toolFileJsonSchemaDefinitions`. `ToolResult.files` is derived from file fields. Capture no longer inserts text labels: captured image/document/audio parts are followed by a `File` part with a `Ref` source, and unstored files are `File` parts with the new `Omitted { reason }` source (`FileSource`); providers render the same text, but readers older than this release cannot decode transcripts holding `Omitted`. Capture is idempotent. `ModelVisibleToolError` gains `code`. The tool ledger stores typed values whole (content cut first) or, when the value alone is over the bound, a fixed error result.
- `@yolk-sdk/codemode`: typed tools resolve to their declared value (arrays and primitives included, nothing merged); a typed result without a value rejects `<label>: returned an invalid result`; untyped tools resolve to their text parts only; failures reject with the text and `error.code` (also through the pi executor). Breaking for scripts: no more `files` merged into values or `{ text, files }`. The description declares `FileRef`/`FileUnavailable` and says `string` results are text; signatures show file fields by name.
- `@yolk-sdk/mcp`: adapted tools declare `{ value, files }` and `callRemoteMcpServerTool`/resumable calls return `mcpToolResult`: `value` is `structuredContent`, else the text parsed once when it is one JSON object or array, else the text; blobs, images and audio are file fields. Breaking for scripts and for hosts reading MCP `structuredContent`.
- `@yolk-sdk/connectors`: `fileOutput` actions (`gmail`/`outlook`/`email` `get_attachment`) declare `{ value, files }` with file fields instead of trailing `FilePart`s.
