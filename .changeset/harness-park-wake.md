A park that stops blocking no longer strands work. New `Driver.clearPark(runId, generation)` drops a park without its answers and wakes the run when input was admitted while it blocked, so those messages are answered (#294). `DriverApi` gains this as a required `clearPark` member: custom `DriverApi` / `Driver.of` implementations must add it. `Inbox.clearPark` now takes that wake effect as a third argument, as `acceptHitl` does; direct callers and custom `InboxApi` adapters must pass it. When the continuation of a Ready park (all HITL answers in) fails with a defect, the run keeps its claim instead of releasing it with the answers parked and nothing scheduled (#296), also when a successor woken behind that defect skips and succeeds; `RunCoordinator.layer` gains the `keepClaimOnSettle` option behind this, asked whenever an owner settles without interruption. A later `resumeSuspended` in the same process re-delivers the answers under `maxResumeAttempts`, so hosts that want in-process recovery after a crashed continuation run `resumeSuspended` during runtime, not only at boot; after a restart the host rebuilds the park from its checkpoint. On exhaustion the claim is released but the park stays Ready, so the next admit or wake replays it with a fresh budget. Other drain defects still release the claim, and nothing retries automatically.
