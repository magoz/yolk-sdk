Add the experimental, Node-only `@yolk-sdk/emulators/dropbox` and `@yolk-sdk/emulators/notion` subpaths: `makeDropboxEmulator` and `makeNotionEmulator`, stateful emulators on the pinned `@emulators/core` custom runtime (loaded lazily) that follow the fixture-only rule. The Dropbox emulator serves the `/2/files` RPC routes the Dropbox conformance cases use (`list_folder` and `continue`, `get_metadata` with `include_deleted`, `search_v2` and `continue_v2`, `create_folder_v2`, `delete_v2`, `copy_v2`, `move_v2`) on `api.dropboxapi.com` and the `upload` route on `content.dropboxapi.com`, with the fixtures' HTTP 409 `error_summary` envelopes byte for byte, case-insensitive paths, and strict upload rev preconditions. The Notion emulator serves the `/v1` routes the Notion conformance cases use at `Notion-Version: 2025-09-03` (search, the bot user, page read, create, and archive, block children, paginated property items, and the database / data source split) with cursor paging and the fixtures' error envelopes. Both are seeded by default with the synthetic fixture entities so the conformance cases (and their leftover lookups) run unmodified, answer everything the fixtures do not show with one ledgered 400 not-emulated before any fault is used up, list their few extrapolations and one request-shape latitude bullet each, and add status faults (400-599), a credential-free ledger, an `/_emulate/*` control plane, test-only drill knobs (one per case), and `dropboxEmulatorRoutes` / `notionEmulatorRoutes`, route evidence manifests linked to the conformance case ids (all routes unverified).
