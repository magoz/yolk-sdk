'@yolk-sdk/emulators': patch

Add the experimental, Node-only `@yolk-sdk/emulators/dropbox` and `@yolk-sdk/emulators/notion` subpaths: `makeDropboxEmulator` and `makeNotionEmulator`, stateful emulators on the pinned `@emulators/core` custom runtime (loaded lazily) that follow the fixture-only rule without exceptions. The Dropbox emulator serves the `/2/files` RPC routes the Dropbox conformance cases use (`list_folder` and `continue`, `get_metadata` with `include_deleted`, `search_v2` and `continue_v2`, `create_folder_v2`, `delete_v2`, `copy_v2`, `move_v2`) on `api.dropboxapi.com` and the `upload` route on `content.dropboxapi.com`, each only on its recorded origin (`fetchOn(origin)` serves one origin behind a loopback rewrite), with the fixtures' HTTP 409 `error_summary` envelopes byte for byte, case-insensitive paths, and strict upload rev preconditions. The Notion emulator serves the `/v1` routes the Notion conformance cases use at `Notion-Version: 2025-09-03` (search, the bot user, page read, the recorded create, archive, block children, paginated property items, and the database / data source split) with cursor paging and the fixtures' error envelopes. Both are seeded by default with the synthetic fixture entities (entities a fixture only names are held as implied and never rendered) so the conformance cases run unmodified. Every answer value comes from a fixture or is a minted value (ids, revs, hashes, cursors, request ids, clock timestamps); cursors are accepted only when issued by the emulator for the same unchanged list since the last reset. Everything else answers one ledgered 400 not-emulated, writes nothing, and uses up no fault: each route checks the request shape and then, reading the state without writing, its eligibility before a fault is decided. That includes an empty folder listing and a search without matches (no fixture records either), so the read-only leftover lookups fail against the default seeds and the runners print their lookup-failed WARN. Both add status faults (400-599), a credential-free ledger (credential-named keys in bodies, queries, and the `Dropbox-API-Arg` header are redacted), an `/_emulate/*` control plane, test-only drill knobs (one per case), and `dropboxEmulatorRoutes` / `notionEmulatorRoutes`, route evidence manifests linked to the conformance case ids (all routes unverified).
