A resumed run's tool batch no longer lands on an earlier turn's call that reused its id (#352). The loop resumes a pause with `AgentStart`, then the paused batch (answers, starts, results) before its first model turn; `AgentStart` cleared the turn start, so `reduceAgentEvents`, `applyAgentEventToChatProjection` and the `useAgentChat` reducer acted on the last run or part holding the id, in any turn: a resumed result replaced an earlier turn's `Accepted` background run or `Completed` call, and a resumed answer overwrote an earlier turn's completed run.

- `AgentStart` now records a run start instead of clearing the turn start (`turnStart` with turn `0`, the new optional `run: true`, after the runs or messages kept so far; `AgentClientTurnStart` also `closed`, `AgentChatTurnStart` gains `run`). `submitAgentUserMessage` and the `useAgentChat` reducer's local submit, HITL answer, regenerate and edit record one too, for hosts that stream without `AgentStart`. Host events then reach an earlier turn's run or part only as the same call (id, name and arguments equal) or, for answers, the run or part holding the request they answer; otherwise they add their own. The model's events before the run's first `LLMStreamStart` replay an earlier run's and act as with no start known, so replays of an accepted call keep their fence. The run's first `LLMStreamStart` starts a new turn. States without `run` (built before it) behave as before.
- `reduceAgentEvents`: an answer whose call the latest turn lacks and whose request no run holds now adds a run (a resumed answer whose pending run `AgentStart` dropped) instead of being dropped when another turn holds the id; an answer reaching a latest-turn run that holds another request still changes nothing.
- The chat's replayed-start fence now matches the client's: a `ToolExecutionStarted` of the same call (id, name and arguments equal) leaves a `Completed`, `Accepted` or `Errored` part, and the `useAgentChat` reducer's status, alone (before: `Completed`/`Accepted` by id; an errored call went back to `Running`). A start naming another call with the id applies to a completed or errored part (an accepted part keeps ignoring every open state, as before).
