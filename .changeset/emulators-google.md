Add the experimental, Node-only `@yolk-sdk/emulators/google` subpath: `makeGoogleEmulator`, a stateful emulator on the pinned `@emulators/core` custom runtime (loaded lazily) that follows the fixture-only rule. It serves exactly the Gmail, Calendar, and Drive routes the thirteen Google conformance cases and their cleanup use, each on its recorded origin (`https://gmail.googleapis.com` for Gmail and the multipart send upload, `https://www.googleapis.com` for Calendar and Drive): label listings with page tokens, message reads in the recorded `format` renderings, attachments, the label lifecycle, label changes, trash and untrash, the draft lifecycle and its thread, the practice send, Calendar range listings and the run event lifecycle (a deleted event stays readable as `cancelled`; a repeated delete answers the recorded 410), and Drive folder listings, file reads, and the run folder lifecycle. The practice send is only recorded in the state, never delivered, and only the recorded 7-bit message whose sole recipient is the seeded practice address (the recorded `practice@example.test`) is accepted; draft and send subjects take only a run id of the fixtures' 13-character length, since the recorded `sizeEstimate` covers the subject. Anything the fixtures do not record answers a ledgered 400 not-emulated before anything is written and before any fault is chosen, including an empty listing and every read of the leftover lookup, which therefore fails closed. The emulator uses the shared wrapper's existing opt-in fail-closed mode: an unrecognisable `Authorization` header or a request on no route shape is ledgered with constant text only, and the bearer value is never stored or ledgered, scrubbed from every refusal, and refused when the path, query, recorded `content-type` header, or body repeats it. The shared internal wrapper gains one backward-compatible, opt-in hook for this, `decodedViews`: a route may name decoded views of its raw body (the Google draft compose and update routes give the base64url-decoded MIME of `message.raw`, which Gmail's own wire format wraps), and in fail-closed mode each view is checked for the bearer like the raw body before anything is recorded, a fault is decided, or anything is committed. A view may throw to refuse a body it cannot check completely; the request is then ledgered as a constant entry: a credential repeat when the thrown `DecodedViewRefusal` carries cleanly decoded text holding the bearer, else the refusal's reason when the route declares it in `viewRefusalReasons` (constants the route owns, never derived from a request), else `the request body cannot be checked for the credential`. The Google draft routes refuse any `message.raw` that is not canonical unpadded base64url of exactly the recorded draft MIME with their own declared reasons (the 13-character run-id reason among them), so a refused `message.raw` never reaches the ledger. Routes without it, including every GitHub, Dropbox, and Notion route, are checked exactly as before. Includes status faults (400-599), clock-free error recovery, an `/_emulate/*` control plane, test-only drill knobs, and a route evidence manifest (`googleEmulatorRoutes`, all unverified; the fifteen write routes are pending until an owner-approved live run).
