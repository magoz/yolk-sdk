Add the experimental, Node-only `@yolk-sdk/emulators/microsoft` subpath: `makeMicrosoftEmulator`, a stateful Microsoft Graph emulator on the pinned `@emulators/core` custom runtime (loaded lazily). It serves only the Graph v1.0 routes the Microsoft conformance cases use (calendar view with overlap filtering, event create/get/update/delete/cancel, folder message paging with an opaque `@odata.nextLink`, draft create/update/move with immutable ids, attachment listing and retrieval, `$batch` permanent delete, and OneDrive item read, children listing, folder create, delete, and file copy) plus the OneDrive copy monitor URL on a SharePoint origin, seeded by default with the synthetic Microsoft fixture entities so the Microsoft conformance cases run unmodified. Its behaviour comes only from the conformance fixtures, including their `@odata.context` envelopes; anything they do not show fails closed with the Graph error envelope, and the few extrapolations the cases need (plus one opt-in) are documented. For concurrent writes, the first write to reach the handler holds the message for `conflictWindowMs`; an overlapping write gets 409 `ErrorIrresolvableConflict`; non-overlapping writes both apply (an emulator extrapolation). It adds status faults, a credential-free ledger (credential-named body and query keys are redacted), an `/_emulate/*` control plane, test-only drill knobs, and `microsoftEmulatorRoutes`, its route evidence manifest linked to the Microsoft conformance case ids (all routes unverified). A Fortnox route handler that throws now answers an evidence-tagged 500 `ErrorInformation` recorded in the ledger, like the Microsoft emulator.
