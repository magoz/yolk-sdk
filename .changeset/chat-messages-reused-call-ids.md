`buildAgentChatMessages` no longer gives one tool run to every card with its call id, across turns (#356). `toolRuns` can hold one run per turn for a reused id (`reduceAgentEvents`), and snapshot hosts pass runs of several turns (pending requests from `toolRunsFromHitlRequests`, accepted interaction receipts); the last run by id used to show on every card with the id, so an earlier turn's accepted interaction and a later turn's pending approval on `call_0` both showed the approval (or, in the other order, the actionable card was hidden).

- Each run goes to one card, later runs first, each card taking at most one, so one run per turn of the same call lands on its own turn. A run holding a call (its own, or its request's) takes the last card holding the same call (id, name and arguments equal); when no card holds it (arguments a host normalized), the last card with its id and name that no run took and that has no result message, so a pending request is never hidden; a run whose call has another name (another turn's call, not in `messages` yet) shows nowhere (before, it showed on the last card with the id). A run holding no call (an input still streaming, an answer or denial without its request) that answers an earlier run's request takes that run's card, so a later denial still wins over the approval it denies; otherwise it takes the last card with its id that no run took, one without a result message first (as before for a single card).
- A `ToolResult` message now belongs to the last card with its id before it: a later turn's call reusing the id no longer shows an earlier turn's result (or its background acceptance, which hid the later call's pending request), and an earlier call no longer shows a later turn's result. A result with no card before it shows as its own message instead of attaching to a later call.
