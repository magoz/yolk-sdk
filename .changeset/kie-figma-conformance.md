Add the experimental `@yolk-sdk/connectors/kie/conformance` subpath: six Kie conformance cases (`kieConformanceCases`) with `KieConformanceConfig` seeds and minimal synthetic replay fixtures (`kieConformanceFixtures`, `evidence: 'unverified'`; an allowlist test checks every body). Four reads run the real `kie.get_task`: a finished task reads back `success` with https result URLs parsed from `resultJson`, a failed task is a successful read with a failure detail, an unknown task id answers a 4xx envelope `code` (Kie answers most failures with HTTP 200 and a non-200 envelope `code`), never a success, and a synthetic invalid key answers `kie_unauthorized`. Two `write-irreversible` cases run the real `kie.create_image_task` (GPT Image 2, square at `1K`) and `kie.create_video_task` (Wan 2.7, `720p` for 5 seconds): every task spends credits and the connector cannot cancel one, so each runs only by its exact id, uninterruptibly with its classification (a definitive HTTP or envelope 4xx other than 408 and 455 created nothing; anything else that is not a 2xx with envelope `code` 200 is an unknown task outcome naming the run id). Add the experimental `@yolk-sdk/connectors/figma/conformance` subpath, following the Afloat pattern: no case code and no `@yolk-sdk/mcp` import; `makeFigmaMcpConformanceTarget()` runs the real `figma.mcp_auth` and answers the target value (`https://mcp.figma.com/mcp`, the access token as `Authorization: Bearer`, never the refresh token or client credentials, the legacy era with protocol `2025-11-25`, unverified), seeds naming six known Figma tool names with synthetic schemas, and eight synthetic placeholder fixtures (every case but `mcp.modern.stateless`). Add the experimental, Node-only `@yolk-sdk/emulators/kie` subpath: `makeKieEmulator`, a stateful, fixture-only emulator of the Kie task read and create routes on the shared wrapper's fail-closed mode with the bearer digest (the recorded records, the not-found envelope, and the 401 for a rejected key kept only as its digest; creates answer a minted task id and are recorded in state, never readable), with status faults, a control plane, one drill knob per case, and a route evidence manifest (`kieEmulatorRoutes`; `POST /api/v1/jobs/createTask` is a connector write pending an owner-approved live run). `@yolk-sdk/emulators/mcp` gains a fourth profile, `figma`, on `https://mcp.figma.com/mcp` (the legacy era, answering the Figma fixtures copied as data in `mcpEmulatorFigmaFixtures`; new exports `mcpEmulatorFigmaOrigin` and `mcpEmulatorFigmaPath`): every legacy session is now bound to the profile that minted it (Figma sessions carry `profile: 'figma'` in the state), and the shared stateful wrapper's route matcher allows one method and template on two recorded origins, picking the route recorded on the arrival origin (tables without such a pair match as before; a `GET` on the Afloat profile's `/mcp` is now refused as recorded on the Figma origin only). No case is observed live yet.
