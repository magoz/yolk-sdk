Add the experimental, Node-only `@yolk-sdk/emulators/fortnox` subpath: `makeFortnoxEmulator`, a stateful Fortnox `/3` API emulator built on the upstream `@emulators/core` custom runtime (a new dependency pinned to exactly `0.12.0`, loaded lazily). It serves company information, customers, and invoices with rows (list, read, update, create, a synthetic PDF preview, and an email send that only records an outbox entry), seeded by default with the synthetic Fortnox fixture entities so the Fortnox conformance cases run unmodified, plus `default`, `empty-company`, and `no-booked-invoices` profiles. It reproduces the observed quirks the cases claim (sticky row discounts on positional row updates, empty customer strings that keep stored values, payment filters that skip unbooked invoices, lowercase `ErrorInformation` rejections, read-only customer `Country`), fails closed on unknown routes and unsupported inputs, and adds status faults, a credential-free ledger, an `/_emulate/*` control plane, and `fortnoxEmulatorRoutes`, its route evidence manifest linked to the Fortnox conformance case ids (all routes unverified). A `quirks` option flips each quirk for disagreement drills in tests.
