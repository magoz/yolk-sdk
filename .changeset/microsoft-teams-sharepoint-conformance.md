Add eight SharePoint site and Teams conformance cases to the experimental `@yolk-sdk/connectors/microsoft/conformance` subpath (nineteen cases in all), each with a synthetic `unverified` fixture shaped from the Microsoft Graph v1.0 docs examples (each fixture's note names its pages). Reads: `microsoft.sharepoint.search-finds-site` (a keyword search lists the seeded site by its comma-separated id), `microsoft.sharepoint.site-drives-libraries` (the site's drives include a document library; a `null` description decodes), `microsoft.teams.chats-list-members` (listed chats carry their members; a listed id reads back), `microsoft.teams.chat-messages-paging` (a `nextLink` naming the chat id unencoded is accepted and leads to new messages), `microsoft.teams.team-channels` (the joined team and its channel read back by id as listed), `microsoft.teams.channel-message-replies` (channel listings hold top-level posts; replies name their post), and `microsoft.teams.meeting-transcripts` (a join link finds its meeting, whose transcripts name it). Write: `microsoft.teams.send-chat-message` is write-irreversible (the connector cannot remove a sent message), runs live only by its exact id, posts plain text naming the per-invocation `runId` and claims the escaped HTML body reads back by the returned id; an ambiguous send fails `MicrosoftConformanceActionFailed` with `sendOutcome: 'unknown'` naming the run id. `MicrosoftConformanceSeeds` gains `siteSearchQuery`, `siteId`, `chatId`, `sendChatId` (a dedicated practice chat the send posts to, kept apart from the paging `chatId`), `teamId`, `channelId`, `channelMessageId`, `meetingJoinWebUrl`, and `runId`. `@yolk-sdk/emulators/microsoft` adds sixteen fixture-only SharePoint site and Teams routes (35 in all) that answer only the recorded exchanges byte for byte, citing their cases; the chat send (a pending write route) answers the recorded send under a minted message id and keeps it in the new `chatMessagesSent` state, with one drill knob per new case. No case is observed live yet. The already released `teams.send_chat_message`, `teams.send_channel_message`, and `teams.reply_to_channel_message` now send with `redirect: 'manual'` and `credentials: 'omit'`, so a 307 or 308 never posts the message twice; host adapters must honor both (a 3xx answer is a send failure). The Microsoft emulator's `empty` profile now refuses every Teams and SharePoint site route with the 400 not emulated (no fixture records an empty listing): the state gains the required `recordedTeamsSites` flag (`true` only under `default`) and `chatMessagesSent`, so a state snapshot taken before this change (from `/_emulate/state` or `snapshot()`) no longer decodes as `MicrosoftEmulatorStateSchema` and is refused.
