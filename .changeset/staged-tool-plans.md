Add staged tool plans (ADR 0005): code mode scripts can stage calls of approval-gated tools that the host marks stageable (`makeTool({ approval, staging })`, `ToolDef.staging`) with a new `stage(name, args)` global instead of running them, and a person reviews the saved plan once through `makePlanReviewTool` (`review_plan({ planId, planDigest })`, an action-backed interaction with response `{ selectedKeys }`). Yolk then applies exactly the selected recorded calls, in staged order and at most once, through the normal execute path and tool ledger (`<reviewCallId>/<n>`), with optional `beforeCall`, `onFailure: 'stop' | 'continue'`, per-tool `staging.precheck`/`staging.preview` hooks, and `previewToolPlan` for review screens. `stage` validates arguments, executes and ledgers nothing, rejects duplicates and calls past `maxCalls`/`maxArgsBytes`, and is not allowed together with direct writes in the same script. Staging requires `resolveTools(..., { plans: { store }, interactionHost })` and one plan review tool; voice and subagent resolutions without them never get it, and direct script calls of approval-gated tools stay fail-closed. New `ToolPlanStore` port with `makeInMemoryToolPlanStore`, `ToolPlan`/`StagedCall` schemas, `NestedToolExecutor.staging`, `ResolvedToolSet.plans`, `CodeModeStructuredContent.codemode.plan`, `makeCodeModeTool({ staging })`, the interaction `unknownOutcome` hook, and `call` on interaction action `validate` inputs.
