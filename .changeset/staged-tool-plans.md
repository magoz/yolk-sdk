Add staged tool plans (ADR 0005): code mode scripts can stage calls of approval-gated tools that the host marks stageable (`makeTool({ approval, staging })`, `ToolDef.staging`) with a new `stage(name, args)` global instead of running them, and a person reviews the saved plan once through `makePlanReviewTool` (`review_plan({ planId, planDigest })`, an action-backed interaction with response `{ selectedKeys }`). Yolk then applies exactly the selected recorded calls, in staged order and at most once, through the normal execute path and tool ledger (`<reviewCallId>/<n>`), with optional `beforeCall`, `onFailure: 'stop' | 'continue'`, per-tool `staging.precheck`/`staging.preview` hooks, and `previewToolPlan` for review screens. `stage` validates arguments, executes and ledgers nothing, rejects duplicates and calls past `maxCalls`/`maxArgsBytes`, and is not allowed together with direct writes in the same script. Staging requires `resolveTools(..., { plans: { store }, interactionHost })` and one plan review tool; voice and subagent resolutions without them never get it, and direct script calls of approval-gated tools stay fail-closed. Hosts may derive plan ids with `plans.planId({ call })` (default the code mode call id; staged keys are `<planId>/s<n>`). New `ToolPlanStore` port with `makeInMemoryToolPlanStore`, `ToolPlan`/`StagedCall` schemas, `NestedToolExecutor.staging`, `ResolvedToolSet.plans`, `CodeModeStructuredContent.codemode.plan`, `makeCodeModeTool({ staging })`, the interaction `unknownOutcome` hook, and `call` on interaction action `validate` inputs. Interaction validators may now fail with `InteractionHostError` when host storage is unavailable (`InteractionCallValidator`, `InteractionPreflight.validateAction`): `prepareToolBatch` then fails with `ToolError` `unavailable` (its error channel is new), `validateInteractionSubmission` answers the new `InteractionAdmissionError` cause `unavailable`, and execution fails closed; an accepted receipt whose call no longer validates is dispatched so the executor can report a receipt another delivery already started or settled. Also adds `previewStoredToolPlan`, `toolPlanKeyPages`, and Effect Schemas `ToolPlanOutcome`, `ToolPlanCallOutcome`, `ToolPlanPreview`, and `ToolPlanPreviewPage`. Applied plan calls bypass `beforeNestedCall` and executor decorators; wire per-call authority through `makePlanReviewTool({ beforeCall })`. With a tool ledger each plan apply runs behind a ledger entry for its review call, so a redelivered execution (receipt `started`) waits for an in-flight apply and returns its real outcome; listings report a selected call without a ledger entry as `not_run` only when provable, else `unknown`. `InteractionToolRegistration.unknownOutcome` receives `phase` (`replay` | `seal`) and may return a proven `outcome` on replay.
