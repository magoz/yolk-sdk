Add the experimental, Node-only `@yolk-sdk/emulators/linkedin-search` subpath: `makeLinkedInSearchEmulator`, a stateful emulator on the pinned `@emulators/core` custom runtime (loaded lazily) that follows the fixture-only rule. It serves exactly the three reads the seven LinkedIn search conformance cases send, each on its recorded origin: the Exa people search (`POST /search` on `https://api.exa.ai`) and the Enrich Layer profile and email lookups (`GET /api/v2/profile` and `GET /api/v2/profile/email` on `https://enrichlayer.com`). Every answer is a fixture's, byte for byte, through the seed, and nothing is written, minted, or read from a clock: a search answers only the results the state holds for exactly its query and `numResults` (the default seed holds the fixtures' answers for `numResults` 10, 3, and 2), a profile lookup a held profile or, for the seeded absent profile, the recorded 404, an email lookup a held profile's recorded email, and a key the seed marks as rejected on an origin that origin's recorded 401 (by default the synthetic invalid keys the two unauthorized cases send). Anything else answers a ledgered 400 not-emulated before any fault is chosen. The emulator uses the shared wrapper's opt-in fail-closed mode exactly as `/github` and `/google` do (the recognisable-bearer rule, constant-text entries for unrecognised requests, unrecognisable `Authorization` headers, and credential repeats through the fixpoint closure, and the constant-reason `exactQuery` and `exactBodyKeys`). The shared internal wrapper gains one backward-compatible, opt-in, general option for it, `bearerDigest` (fail-closed mode only, refused at build otherwise): routes then see a one-way digest of the recognised bearer for the origin the request arrived on (`EmulatedRequest.bearerDigest`), never the bearer, and a digest that throws or repeats the bearer answers the 500 emulator error with no fault used. The LinkedIn search state holds only SHA-256 digests of the rejected keys per origin, so a key a request carries as its bearer, accepted or rejected, never reaches the state, the ledger, a response, or `/_emulate/*`, and seed errors are constant text (a category and a field path, such as `duplicate search at searches[1]`) that never quote a key or any other seed value. The wrapper's constant-reason `exactQuery` also gains a backward-compatible opt-in, `rawNames`: every raw query parameter name (before `URLSearchParams` decodes it) must be the plain name the route takes, so the LinkedIn search lookups refuse a percent-encoded name such as `%6cinkedin_profile_url`. Emulators without either option are unchanged. Includes status faults (400-599), an `/_emulate/*` control plane, test-only drill knobs (one per case), and a route evidence manifest (`linkedInSearchEmulatorRoutes`, all unverified reads, so no pending evidence entry).
