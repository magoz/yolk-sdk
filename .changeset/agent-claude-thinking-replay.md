Show Claude thinking, and send it back so the model keeps its reasoning.

Newer Claude models (Opus 5 and later) think by default but return thinking blocks with empty text unless the request asks for summaries, and the Claude provider never sent a `thinking` field, so hosts received no reasoning. `AnthropicClaudeProviderConfig.thinking` now requests adaptive thinking: `display: 'summarized'` streams readable summaries as `ReasoningDelta`, and `prefixMismatchBehavior` (`'drop_block'` or `'error'`, sent as `block_binding.prefix_mismatch_behavior` with the `thinking-binding-controls-2026-08-01` beta) decides what Anthropic does with a replayed thinking block whose earlier system prompt, tools or messages changed. Without `thinking` the request is unchanged.

Thinking signatures were dropped, so tool-use turns lost the reasoning behind each call, and `redacted_thinking` blocks failed to decode in JSON responses. `AssistantReasoningPart` gains an optional `replay` (`AssistantReasoningReplay`: `SignedReasoningReplay` with the block's signature, or `RedactedReasoningReplay` with its encrypted data, each naming the producing provider). The new `LLMReasoningReplay` event closes a reasoning block with that state; `accumulateAssistantMessage` attaches it to the part and never joins later text to a closed part. It is not an agent event: it reaches the `AssistantMessage` only. The Claude provider captures signatures and redacted blocks, and its lowering sends an assistant message that holds its own replay state back in produced order (thinking, text, tool calls) with the exact text and signature. Other assistant messages keep their existing byte-identical shape, and reasoning from another provider is never sent. Native Messages backends (OpenCode Go) neither capture nor replay signatures. Thinking blocks never carry a `cache_control` marker. `anthropicClaudeReasoningReplayProvider` names the Claude replay provider, so hosts that rewrite history per request can leave those parts untouched.
