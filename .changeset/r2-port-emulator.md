'@yolk-sdk/emulators': minor

Add the experimental `@yolk-sdk/emulators/r2` subpath: `makeR2Emulator`, a fixture-driven in-memory fake backend for the host R2 ports `R2Presigner` and `R2ObjectClient` (no SigV4 signer, S3 client, or Node builtin), exposed as a plain-JSON `call(port, method, request)` that `r2PortsLayerFromBackend` from `@yolk-sdk/connectors/r2-storage/conformance` turns into both port layers. Answers come only from the R2 conformance fixtures (copied as data); a bucket seed decides which fixture answers and records the objects the absent-only and `If-Match` puts create or replace under the etags the fixtures name. It has a ledger, faults (applied only to calls a state-consistent fixture would answer), reset, coverage, and an unverified route manifest whose one write route is `PORT R2ObjectClient.put`. Anything the fixtures do not cover fails closed, and every refusal is ledgered with constant text only (no request text); the only request-shape latitude is ignoring credential fields and JSON key order. Credential fields are dropped before anything is compared or recorded. A put body must be canonical base64 of UTF-8 text (else `uncheckable-body`); it is checked as decoded text and ledgered only as its byte length. A request that repeats any value found under a credential field (of any length, keys and numbers included, raw or through percent, JSON, `\x`, or HTML-reference escapes), or carries a SigV4 credential parameter, another credential query parameter, a bearer token, or an API-key-shaped token anywhere else (the decoded body included), is refused as `credential-in-request`; an own `__proto__` key is `invalid-request`, and a request the checks cannot walk is `uncheckable-request`, so `call` never throws.
